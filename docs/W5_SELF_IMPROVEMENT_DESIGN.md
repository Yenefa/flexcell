# W5 自改进闭环 — 设计（M0）

> 目标：把"失败 → 归因 → 改进 → 回归 → 独立验证 → 能力更新"跑成一条**可复现的链路**，
> 而不是靠人手动改 prompt/参数。

## 1. 现有可复用资产
| 环节 | 已有能力 | 位置 |
| --- | --- | --- |
| 执行失败 | 真实 Gazebo 失败记录（T-G3 cold 0/3、历史 MTC 拒绝） | `runs/*`、`setup/acceptance/*` |
| 独立验证 | `gate/acceptance.py` 重跑真实栈 | pilot-001 实验模板 |
| 证据 | episode、fingerprint、telemetry | 同上 |
| 候选实现 + 回归 | 合成层 harness：agent 可改代码，验收 + 单元测试 | P1.0 / P1.2 的 T-B v1 |

## 2. W5-E1 设计（合成层，低成本）
**任务**：给 agent 一个**失败的实现**（例如 recovery 逻辑在某分支返回错误动作），要求它：
1. 读失败 evidence（telemetry + 验收输出）；
2. 修改允许的文件（技能实现）；
3. 通过**目标验收** + **既有回归测试**（protected 清单外）；
4. 由独立验收判定，成功则记为"verified improvement"。

**两臂（对照）**：
| 臂 | 信息 | 目的 |
| --- | --- | --- |
| W5-A | 只有失败输出 | 基线 |
| W5-B | 失败输出 + 失败分类/证据摘要 | 验证"归因信息"是否降低迭代数 |

**指标**：成功、迭代数、token、是否破坏回归（必须 0）。

## 3. 验收门（冻结）
1. 目标验收 PASS；
2. 既有测试全过（回归损失 = 0）；
3. 修改只发生在允许路径（protected 文件 hash 不变）；
4. 证据完整（结果 + 事件 + 验收输出）。

## 4. 与 W6 的区别
- W6 迁移的是**任务提示里的知识**（prompt 层）；
- W5 迁移的是**代码实现的改动**，并通过回归测试确认没有破坏原能力；
- W5 更接近"self-evolving"的最终闭环，必须端到端演示。

## 5. 阻塞与风险
- 合成层任务的"失败"是人工注入的；这是**受控实验**，不是真实故障；
- 若 agent 直接删除/绕过测试，必须由 protected hash + 独立验收拒绝；
- 真实机器人闭环（M3-R）仍不可达。
