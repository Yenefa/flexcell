# 更正：W5 Level C 系列运行的终止原因（2026-11-10）

## 1. 发现的错误

我此前把 Level C′ / C14 / P2 的失败表述为"**agent 运行了场景但选择不编辑**"。
复核 `events.jsonl` 发现这是**不准确的**：这三次运行都是被**token 预算强制终止**的，
不是 agent 自行结束。

判定代码（`pilot/runner.py:107-108`）：
```python
if tokens > int(budget["max_tokens"]):
    rec.emit("budget_exceeded", tokens=tokens)
```
`T-W5SC2` 预算：`max_iterations=24`、`max_tokens=40000`。

## 2. 实测数据（全部来自归档的 `events.jsonl` / `result.json`）

| 运行 | 迭代 | Token | 预算 40k | `budget_exceeded` | 编辑 | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| Level C′ | 10 | 51,395 | **超出 28%** | **是** | 0 | FAIL |
| C14 | 9 | 53,045 | **超出 33%** | **是** | 0 | FAIL |
| P2 reuse | 7 | 54,142 | **超出 35%** | **是** | 0 | FAIL |
| C15 run_b | 4 | 16,937 | 用 42% | 否 | 1 | **PASS** |
| C15 run_c1 | 5 | 22,077 | 用 55% | 否 | 1 | **PASS** |

## 3. 更正后的表述

**错误说法**：agent 看到了失败证据，但选择不编辑。

**正确说法**：在没有定位信息时，agent 把**全部 40k token 预算**消耗在目录遍历与分段阅读上，
**在预算耗尽前从未到达编辑这一步**；一旦失败证据自带定位，同样任务在 **1/3–1/2 预算**内完成修复。

## 4. 结论是否改变

**核心结论不变，且更强**：
- 定位成本是**主导项**——它把运行推到预算上限（+28%~+35%），而不是小幅差异；
- 有定位时三次里两次在 17k–22k token 内完成，剩下 ~45–58% 预算未用。

**但必须补充一条此前遗漏的限制**：
- 失败运行是**被截断**的，因此**不能**断言"再多给预算也修不好"；
- 也不能断言"agent 在任何预算下都不会编辑"——它在预算内没走到编辑，仅此而已。

## 5. 影响的文件（已同步更正）

- `docs/EXPERIMENT_MATRIX.md`：三个 FAIL 行补 `budget_exceeded=yes` 与 token 占比；
- `docs/24H_RESEARCH_REPORT.md`：机制表述改为"预算耗尽前未到达编辑"；
- `setup/acceptance/*/README.md`：同上。

## 6. 为什么这个错误值得记录

"agent 选择不编辑"是**对行为的解释**；"预算耗尽"是**可测量的事实**。
把后者说成前者，等于用解释替代证据——这正是本轮反复强调的失败模式。
