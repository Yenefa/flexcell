# 更正 #2：Level C 系列失败的真正原因是**预算截断**，不是能力边界

> 本文件**取代** `CORRECTION_20261110B.md` 中"定位成本是主导项、无定位则无法完成"的归因。
> 更正 #1 的事实部分（三次失败均 `budget_exceeded`）仍然成立且已被本实验证实。

## 1. 实验（P3，预注册式单次对照）

唯一变量：预算 40k → **150k**。其余全部相同（无文件名、无行号、无方向、**`suspect_regions` 关闭**）。

## 3. 被推翻的结论

| 我曾说 | 实际 |
| --- | --- |
| "定位成本是硬约束，无定位时 agent 无法完成修复" | **错**。给足预算它会完成，只是要 34 次目录遍历 |
| "C14 的失败机制是工具选择" | **不完整**。工具选择确实低效，但**不是不可克服**，只是更贵 |
| "Level C′ 卡在证据→定位" | **不准确**。它卡在**预算**，遍历策略最终会收敛 |

## 4. 仍然成立的结论（这才是本轮的净发现）

| 条件 | 迭代 | Token | `list_dir` | 结果 |
| --- | --- | --- | --- | --- |
| 无定位 + 40k | 截断 | 51k–54k | 12–34 | **FAIL** |
| 无定位 + 150k | 10 | 48,067 | 34 | PASS（贵） |
| **有定位 + 40k** | **4–5** | **16,937–23,258** | **0** | **PASS（便宜）** |

**定位信息改变的是成本，不是可行性**：
- 迭代 **10 → 4–5（−50%~60%）**；
- Token **48k → 17–23k（−52%~65%）**；
- 目录遍历 **34 → 0**。

## 5. 连带作废

**P2 经验复用实验（54,142 tokens，`budget_exceeded`）同样不能用来否定经验复用。**
它是被截断的，结论只能记为 INVALID，不能记为 H0。
下一轮必须在 150k 预算下重做。

## 6. 教训（本轮第二次同类错误）

两次都是**把"被截断"误读成"做不到"**。
规则应当写死：**任何 `budget_exceeded` 的运行，其"未做某事"都不能作为能力证据。**
