## 2. 主对比：B vs A（族内配对）

**这是唯一被当作主结论的比较。**

| 项 | 内容 |
| --- | --- |
| 配对方式 | 同一 `family` 内，同一 `repetition` 的 A 与 B 配对（同 seed、同缺陷实例、同模型、同预算上限） |
| 比较量 | 自主修复成功率 = `SUCCESS_VERIFIED` / D1（见 [DATA_DICTIONARY.md](DATA_DICTIONARY.md) §4.1） |
| 呈现形式 | 每族一张 3 行配对表（r1/r2/r3 × A/B）+ 一行计数（`x/3` vs `y/3`）+ 差值（整数差） |
| 不做 | 不合并两族求总率；不算 p 值；不给置信区间；不写「显著」 |
| 允许的措辞 | 「与 H1 一致 / 不一致 / 不可判定」+ 计数 |

**判读规则（预先声明，DRAFT-FIXED）**：

| 观察（每族：B 的成功数 − A 的成功数） | 判读 |
| --- | --- |
| 差 > 0 且 A、B 均无 `UNKNOWN` 主导 | 「与 H1 方向一致（n=3，探索性）」 |
| 差 = 0 | 「本设计下未观察到差异（n=3，探索性）」 |
| 差 < 0 | 「与 H1 方向相反（n=3，探索性）」 |
| 任一格 `UNKNOWN` ≥ 2 | 「不可判定（UNKNOWN 占多数）」—— 不给方向 |
| 两族方向相反 | 「族间不一致，不支持跨族结论」 |

## 3. 次要对比：C、D（**仅描述性**）

| 对比 | 说明 | 允许的结论强度 |
| --- | --- | --- |
| C vs B（族内配对） | 检验「反馈必须是本 run 的」；C 用的是预先绑定的 donor run 反馈 | 只能写「C 的成功数 ≤ / = / > B 的成功数」+ 一个**机制解释的候选**，不写因果 |
| C vs A（族内配对） | 若 C ≈ A，提示「失配反馈≈无反馈」 | 同上 |
| D vs B（族内配对） | 分离「信息」与「指示」 | 只能写描述性差异；**不得**把它当成「反馈有用」的证据（D 多了 prompt 级干预，见 [PROTOCOL.md](PROTOCOL.md) §9 L6） |

**硬约束**：C 与 D 的比较**不得**被提升为论文主结论，也**不得**与 B vs A 的结论合并成一句「四条件对比显示…」。

## 4. 错误接纳 / 错误拒绝（分开计，不与成功率混算）

| 指标 | 定义 | 分子来源 | 分母 |
| --- | --- | --- | --- |
| **错误接纳率** | 声称成功但 G1–G4 未全通过 | `false_accept = true` 的记录 | 声称成功的记录数 |
| **错误拒绝率** | 实际达成目标但被某道门拒绝（人工复核确认） | `false_reject = true` 的记录 | 全部被拒记录数 |

规则（DRAFT-FIXED）：
1. 两者**分别**报告，**不**互相抵消，**不**与成功率合成一个分数。
2. 错误接纳的判定依据是**冻结评估器 + #250 契约**，不是修复者的声称。
3. 错误拒绝需要人工复核；必须在报告里写明**复核方法**与复核者身份类别。
4. `false_accept` 与 `false_reject` 都进表，即使为 0 也要写 0（0 是结论）。
5. 若错误接纳 > 0，该条件的成功率**不得**单独作为能力声明，必须与该计数一起出现。

## 5. 全量进表规则（DRAFT-FIXED）

结果表必须**同时**包含下列每一类，缺一类即视为选择性报告：

| 类别 | 呈现要求 |
| --- | --- |
| 成功 | 计数 + 逐条 run_id |
| 失败 | 计数 + 失败的门（G1/G2/G3/G4）+ 逐条 run_id |
| 预算耗尽 | 单列计数 + 耗尽位置 |
| 未知 `UNKNOWN` | 单列计数 + 停止条件码（S1 等） |
| 无效 `INVALID` | 单列计数 + 失效原因码（`DEV-*` / 边界失守） |
| 未派发 `NOT_RUN` | 单列计数 + 原因 |
| 偏差 | 每个 `deviation_code` 的计数与受影响槽位 |

**必须一起读的三点**：

1. **没有一条是 `SUCCESS_VERIFIED`**：独立裁决门始终 `NOT_RUN`，门判 PASS 只记终态 `UNKNOWN`。
2. **`BUDGET_EXHAUSTED` 不等于修复失败**：它表示 agent 未宣告完成，而门是在循环结束后独立判的。F1-D-r3、F2-A-r2 都是「耗尽但门判 PASS」。
3. **F2 的 B 组 1/3 是方差，不是效应**：同 3 槽重跑得到 3/3（见 `f2b_reproduce.json`）。n=3 且单模型，任何单格差异都不可解读为条件的因果效应。

**接口的影响必须一并报告**：这批数据来自给 agent 装上 `read_file` / `search` / `edit_file` 之后的版本。在那之前的 24 槽（`real_instances_matrix_writeonly_INVALIDATED.json`，187,741 tokens）全部失败：只有整文件重写时，模型把 1578 行的节点替换成了 18 行的存根。两组数不能互相印证，只能用来说明「接口决定了任务是否可解」。

### 6.0 已有观测（**尚不可进入本表**）

到这里为止，机器上真实跑过的批有四次，性质各不相同。**四次都不进 §2 的配对对比**，因为 §1 的纳入口径要求记录对着 `DEF-F1-REG` / `DEF-F2-MAP` 这两个已预注册的缺陷实例，而它们跑的是合成 fixture。

| `real_matrix.json` | 24 | 157,776 | 否 | 合成 fixture；当时的 `build_candidate` 不接受 seed，三次重复是同一输入；运行时源码未提交，无源码 SHA；C 的 donor 是合成文本 |
| `confirmatory_f1bc.json` | 4 | 10,361 | **是** | seed 配对、C 借用同族另一 seed 的 B、源码 `5458f1d`；**但**仍是合成 fixture，且独立裁决门 `NOT_RUN` |
| `real_instances_pilot.json` | 4 | 35,140 | 否（该批作废） | **真实例 + 真模型**，但槽位仍沿用合成契约的 `editable_fields="skill/"`：agent 只写了 `skill/`，从未触碰实例，四条全部 FAIL 是跑批器的错，不是模型能力；已标 `INVALIDATED`，仅留证 |

**这批观测能说明什么**（写进 #254 时必须带上这个限定）：在合成缺陷上，真实反馈组 6/6 由契约门判 `ACCEPT`、平均 2.2 次交互；失配反馈组 3/6、平均 4.5 次交互；无反馈组 3/6、平均 4.7 次交互。方向与协议预设一致。

**不能说明什么**：不能当作"修复能力的成功率"，因为(a)任务不是预注册实例，(b)独立裁决门没跑，`ACCEPT` 只是契约门的一家之言，(c)单模型、每组 3 次重复。

> 记录这些不是为了给论文凑数，而是相反：**把"跑过了"和"能入表"分开写清楚**。否则下一轮有人看到 24 行有数字，会以为 §2 的主对比已经有结果了。

## 8. 预先声明的判读流程

1. 先出 §6.1 矩阵总表（含 `NOT_RUN` / `INVALID`），**不看成功率**；
2. 再出 §6.4 资源表，确认四条件的预算消耗可比；
3. 再出 §6.3 错误接纳/错误拒绝表；
4. 最后才出 §2 主对比与 §3 次要对比；
5. 结论段按「与 H1 一致 / 不一致 / 不可判定」三选一写，**每族各写一句**，不合并；
6. 任何一处提到数字，必须同时给出 `n`。

## 10. 已知限制

- 截至本轮，**没有任何记录对着预注册的 `DEF-*` 实例跑过**。注入文件已落成（`experiments/repair_eval_v02/defects/`），但把感知服务与任务 FSM 在仿真里跑起来这件事尚未发生。

- 本文件写于**无数据**状态，因此所有判读规则都是**事前**的；若运行后发现规则不可用，
  只能在 [PROTOCOL.md](PROTOCOL.md) §8 登记偏差并升版本，**不得**悄悄改。
