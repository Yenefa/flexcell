# 字段语义：`claim_success` 与它的误用

> 本文件回答一个具体问题：能不能用旧记录里的 `claim_success` 字段证明"独立验证是有效的"。
> 答案是**不能**，理由是实测的分布，不是观点。

## 1. 字段是什么

旧记录（`experiments/pilot-001/pilot/*.py`）每条 `result.json` 带三个相关字段：

| 字段 | 谁写的 | 含义 |
| --- | --- | --- |
| `claim_success` | FCAgent适配器字段（历史路径固定为false） | 不是判定，是声明 |
| `success` | 独立 judge 跑 `gate/acceptance.py` 后写 | 判定 |
| `false_success` | 两者不一致且 agent 声称成功 | 错误接纳的计数位 |

## 2. 实测分布（本轮重算）

在 19 条归档记录中：

- `claim_success == true`：**0 条**
- `false_success == true`：**0 条**

也就是说：**这个字段在所有历史记录里恒为 false**。

## 3. 为什么这很重要

一个恒为 false 的字段，**无法区分任何两件事**。如果论文写"我们观察到 false_success = 0，
说明独立验证有效"，那这句话是空的：

- 它不可能不为 0——字段在样本里从未取过 true；
- 一个坏掉的验证器同样会给出 0；
- 而 W5-E2b/E2d 里 agent 明明把任务做成了（`success=true`），它却仍然报 `claim_success=false`，
  原因是历史 `FCAgent.step()` 在工具调用和无工具调用分支均固定返回 `claim_success=False`。该路径没有记录模型的成功自评，不能据此推断模型从不表态。

这正是 #250 把那套契约重新做一遍的原因：新的 `evaluate()` **不读** `claim_success`，而是
读冻结契约里的目标/容差/回归/证据/退出码，并把失败分成 `REJECT`（测到了违规）与
`UNKNOWN`（测不了）两种。

## 4. 论文里应该怎么写

**不要写**

- "false success rate = 0，说明验证有效"
- "agent 的自我评估与独立判定一致"（样本里 agent 从未声称成功，谈不上一致）

**可以写**

- "在归档的 19 条记录中，适配器输出的成功声明字段固定为 false，因此该字段不能用于评估模型自评或验证有效性；
  我们改用冻结契约的独立判定，并分别统计错误接纳与错误拒绝。"
- 同时给出：契约层的 7 个用例（6 负例 + 1 正例）实测 false_accept = 0、false_reject = 0，
  **并注明这是合成夹具上的结果，不是机器人运行结果**。

## 5. 一个仍然存在的缺口

即便换成契约判定，"错误接纳"在**真实运行**上仍未被测量过——#250 的语料是合成的。
要真正回答"验证器会不会放行一个错误修复"，需要 #252 在真实记录上统计，这正是它的主指标之一。
在拿到那些记录之前，任何关于"验证有效"的陈述都只能限定在合成夹具范围内。
