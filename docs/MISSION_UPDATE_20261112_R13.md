## §19.1 本轮：先推翻我上一轮的解释，再找到真的那个

第 10 轮我说「不可控变量是工具姿态」（因为 `orientation_error_rad` 是 0.44–1.02 rad）。
**在基于它做事之前我先验了它，它是错的。**

那个 0.44–1.02 rad 是**相对请求的单位姿态**的误差——一个系统性偏移，不是逐次散布。
把**不同 run 在同一指令位姿**上的到达姿态两两比较：

| 指令 x | run 数 | 最大姿态差 |
| --- | --- | --- |
| 0.1425 | 4 | **4.5°** |
| 0.1615 | 5 | 2.5° |
| 0.1805 | 5 | 3.7° |
| 0.1995 | 5 | 3.5° |
| 0.2575 | 10 | 3.4° |

**姿态可重复到 1.4–4.5°。它不是不可控变量。第 10 轮的解释撤回。**

## §19.2 真正在变的是什么

- 方块起点：**每一次都是 `[0.22, 0.0, 0.0175]`，零方差**
- 姿态：可重复到几度
- **到达的末端高度：0.0198 – 0.0249，约 5 mm 散布**

而已提交的高度扫描在这个区间极其敏感：

```
0.0215 -> 151 mm      0.0240 -> 70 mm      0.0265 -> 6 mm
```

**5 mm 的散布正好横跨这道悬崖。** 这是没有自由参数的定量机制。

## §19.3 预注册实验：被证伪，而且证伪的方式把这条路关死了

**预注册**：把 `contact_height_m` 从 0.0175 降到 **0.0100**，预测到达高度 0.012–0.018、位移 ≥0.060。

**实测：0 / 3，全部 `ec=30`、零位移。**

原因不是 harness 故障：

```

              ik_precheck.ok = True        detail = 'IK solution found'
```

**IK 能解，机械臂执行不了。可达下限在被指令高度之上——所以这道悬崖用请求字段逃不掉。**
