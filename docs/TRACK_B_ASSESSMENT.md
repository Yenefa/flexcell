## 1. 路由协议（代码实测）

`src/flexcell/flexcell_skills/flexcell_skills/hybrid_policy.py`（`HybridRouter`，v1.1）：

```
fast 提案 ──► safety gate ──► confidence ≥ τ 且 calibrated? ──是──► 采用 fast
                 │                        │
                 │ 拒绝                    └──否──► slow 提案 ──► safety gate ──► 采用 slow
                 └──► 计入 rejected_proposals                └──► 都不可用 ──► FSM fallback
```

要点（均有代码依据）：
- **router 从不派发 skill**；两条提案都过**同一个纯 safety gate**；executor 再门禁一次；
- `require_calibration=True` 时，**未校准的 fast 置信度一律不算数**，强制升级到 slow；
- fast 不可用或阈值不可达时**整体 bypass**（`fast_bypassed`），不留半状态；
- 两级 fallback：slow 也不可用 → FSM；FSM 状态机不匹配 → **typed `POLICY_FAILURE` abort**，
  而不是假装能重放；
- provenance 是结构化字段，**不从解释字符串解析**。

## 3. 已有实测证据（E-021，历史归档，未在本轮复跑）

E-021：同一台机器、同一晚、无人值守，S1 双物体任务，**每臂 n=20**，FSM 作对照。

| 臂 | 成功率 | Wilson 95% CI | 付费慢模型占比 | 成本上限 |
| --- | --- | --- | --- | --- |
| **FSM 对照** | **19/20 (0.95)** | [0.76, 0.99] | 0/163 = 0% | ¥0 |
| hybrid τ=0.03 | 18/20 (0.90) | [0.69, 0.98] | 5/156 = 3.2% | ~¥0.02 |
| hybrid τ=0.85 | 17/20 (0.85) | [0.64, 0.95] | 26/159 = 16.4% | ~¥0.3 |

**三个置信区间全部重叠** → n=20 下**无显著成功率差异**。

## 4. 结论（这是本轮 Track B 的净判断）

| 问题 | 回答 |
| --- | --- |
| Hybrid 能跑吗？ | **能**，协议 + 69 项离线测试 + 历史 n=20 实测 |
| 比 FSM 更成功吗？ | **没有证据**。CI 重叠，点估计还**略低**（0.85–0.90 vs 0.95） |
| 比 FSM 更便宜吗？ | **不是**。FSM 成本 ¥0，hybrid 最高 ~¥0.3 |
| 比 FSM 更快吗？ | **未测**。历史批次没有记录端到端时延对照 |

**所以"不得因为 Hybrid 成功运行就宣称策略优越"这条约束，恰恰成立**：
它确实运行了，但**没有任何一个维度优于 FSM**。

## 5. 为什么本轮不再加实验

要让 hybrid 展示优势，需要一个**两种策略会给出不同决策**的场景。
E-021 用的是普通 S1 抓放——在这种场景下 FSM 几乎总对，模型只在无关紧要处花掉预算。
再加 n=20 的同类样本，只会把 CI 收窄，**不会改变"没有优势"这个结论**。
这违反"不得重复执行没有新增信息价值的实验"。

## 6. 下一轮该做的（可证伪）

**命题**：在"观测噪声导致 FSM 的确定性规则给出错误动作、而模型能从上下文纠正"的场景中，
hybrid 的成功率显著高于 FSM。

需要构造的场景特征：
1. FSM 的规则在**该实例上**会选错（例如目标被遮挡后重新观测到不同 id）；
2. 模型有足够上下文能选对；
3. **必须有 FSM 对照臂**，且两者跑同一批实例。

若构造不出来，就应当**如实记录为负结果**：hybrid 在本项目的场景族中没有优势，
并把资源转回 FSM 侧的可靠性（本轮整改的方向）。
