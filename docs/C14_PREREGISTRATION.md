# C14 预注册 — 工具清单可见性对无提示定位的影响（Level C″）

**预注册时间**：2026-11-10T11:05+08:00（运行前）

## 1. 观察到的现象

Level C′（有效判分）结果 FAIL：10 轮、51,395 tokens、**9 次运行场景**、**0 次编辑**。
复盘工具调用轨迹发现一个未被预料的事实：

> **该臂拥有 `search_code` 工具，但 agent 在整个会话中一次都没有调用它。**

它反复使用 `list_dir`（12+ 次）和 `read_file`，从未尝试用搜索缩小范围。

## 2. 可证伪命题

**H2**：agent 的失败主因是**工具选择**（不知道有哪些工具/能做什么），而不是"无法从证据定位"。
若在系统提示中**显式列出所有可用工具及其用途**（不提示该用哪个、不提示答案），
agent 会在前几轮内调用 `search_code`，并在预算内完成修复。

**H0**：即使工具清单可见，agent 仍不搜索、仍不编辑 → 瓶颈确在定位/推理，而非工具可见性。

## 3. 唯一改动（相对 Level C′）

`SYSTEM` 提示新增**工具清单**：每个工具的**名称 + 一行用途**。
- **不**点名哪个工具适用于本任务；
- **不**给出文件名、行号、参数或修复方向；
- 任务文本 `TASK_C` 与 C′ **完全一致**（含"先运行场景"那句）。

这是允许的：Level C 规则明确"可以告诉 Agent 预期行为、失败现象及**可用工具**"。

## 4. 判据（运行前固定）

| 观察 | 判定 |
| --- | --- |
| 调用 `search_code` ≥1 次 且 发生源码编辑 且 三门 PASS | **支持 H2** |
| 调用 `search_code` ≥1 次 但未修复 | 工具可见性不足解释失败 → **H0** |
| 仍 0 次 `search_code` | **H0**，且说明是工具选择惯性 |

单次运行，`T-W5SC2` 预算（24 轮）。**n=1 探索性**，与 Level B/C/C′ **分开统计**。
