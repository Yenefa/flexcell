## §19.3 失败说明了什么——比一次通过更有价值

六次运行的**指令参数完全相同**（`contact_height_m = 0.0175`、`overdrive_m = 0.005`、
`distance_m = 0.09`、同方向）。位移分别是：

```
0.0000   0.0128   0.0363   0.0413   0.0820   0.1018   米
```

**一条指令，0 到 102 mm 的散布。这个推是不可重复的。**

这彻底改变了第 8 轮的读法：**那次 0.1058 m 不是「配置可用」，是「从一个我不知道宽度的分布里抽到的一个样本」。**

## §19.4 接触高度到底买到了什么

| | 旧高度 0.0200 | 新高度 0.0175 |
| --- | --- | --- |
| 实测位移 | 69.92、10.40 mm（两个样本） | 0、12.8、36.3、41.3、82.0、101.8 mm（六个） |
| 观测上限 | 69.9 mm | **101.8 mm** |
| 满足 push 子句 | 记录的运行里 0 | **2 / 6** |

降低接触点到方块中心**抬高了上限，但没有让推动变得可靠**——六次里仍有四次丢失接触。
**接触高度是必要条件，不是充分条件。**

第 6–7 轮说卡点是可达性，错了；第 8 轮被过度解读为「配置可用」；
**本轮表明剩下的问题是接触的可重复性——这是控制问题，不是几何问题。**

## §19.5 失败归因（十类）

| 实例 | 错误 | 类别 | 依据 |
| --- | --- | --- | --- |
| 5000、5003 | ec=28/36 但任务子句满足 | **Control**：任务已满足后接触丢失/过冲 | 实测位移 + 区距 |
| 5001 | ec=28，12.8 mm | **Control**：早期丢失接触 | 实测 |
| 5002 | ec=30 `ERR_MOTION_FAILED`，0 mm | **UNKNOWN**：单次运动失败不能区分控制缺陷、瞬态还是 harness 故障 | 未调查 |
| 5004、5005 | ec=28，36–41 mm | **Control**：中途丢失接触 | 实测 |

`ec=30` 记为 **UNKNOWN** 是刻意的：一个零位移的运动失败可能是控制缺陷、瞬态或 harness 故障，
单样本无法区分，把它叫「控制」就是这个项目已经犯过六次的「用标签替代原因」。

## §19.6 一次被丢弃的实例集（未运行）

第一版（seeds 4000–4005）变化的是**方块位置**。我在检查
`/home/ros/flexcell-p14/scripts/sim_profile.py` 后发现它**总是把 `target_box_a` 生成在 (0.22, 0.0)**——
它能设置 `zone_2`，但无法设置任意方块位姿。

所以那六个实例会让评测按 spec 的区评分，而模拟器把方块放在别处——**正是已记录在案的实例位姿缺陷。**

**我在任何运行之前丢弃了它们**，改为只变化**区的位置**（模拟器不需要放置区）。
因此本轮支持的声明相应收窄为：**关于区位置的泛化**，不是关于方块位置的泛化。我把它写清楚，
而不是让「六个未见实例」暗示更多。
