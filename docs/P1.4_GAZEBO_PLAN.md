# P1.4 — 把 P1.x 接到 Gazebo（M3-S 计划）

> 现状：P1.0–P1.3 的执行层是**合成执行模型**（可达性/超调），不是物理仿真。
> 目标：让同一套三臂 harness 跑真实 Gazebo/ROS 2 执行，达到 **M3-S**（仿真执行 + 独立验证 + 完整证据）。

## 1. 可复用的现有资产
- `scripts/sim_smoke.py` / 核心窗口：本机 WSL 已能跑（A/B 7.47/2.78 mm，恢复 10.22 mm）；
- `test/composite_probe.py`：composite 链 `OUTCOME_SUCCEEDED`（14.6 s）；
- `infra/runtime_identity.py`：指纹与 `installed/source identity` 校验；
- 现有 CI `trusted-simulation` job 的启动/清理脚本。

## 2. 设计（最小改动）
1. **Task adapter**：把 T-A/B/C 的 `gate/sim.py` 替换为 `gate/gazebo_sim.py`：
   - 启动一次仿真栈（或复用常驻栈），执行单个技能/组合；
   - 用**独立验证器**（现有 Verify）产出 verdict；
   - telemetry = episode/decision/evidence 摘要（不含 verdict）。
2. **生命周期**：每个 run 独立 ROS_DOMAIN_ID + Gazebo partition；run 前清理 `gz sim` 残留；超时 180 s。
3. **证据**：episode/decision/verify/fingerprint 四项必须齐全（复用 evidence.py）。
4. **成本控制**：每任务每臂先跑 1 次验证链路（9 次 ≈ 15–25 分钟），再决定是否扩到 n=3。

## 3. 验收（M3-S）
- 单任务单臂：`success` 与 Verify 一致；`false_success=0`；证据完整度 1.0；
- 记录 `runtime_fingerprint` 与 `window_id`；
- 不修改验证器/阈值/世界；失败保留非零退出与日志。

## 4. 风险
- 本机无 GPU（llvmpipe），物理精度有限；
- 仿真启动/清理耗时占大头，token 预算不是瓶颈；
- 需要避免与现有 CI 的 trusted-simulation job 竞争资源。
