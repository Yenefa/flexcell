# C15 预注册 — 失败证据自带定位（Level C″″）

**预注册时间**：2026-11-10T11:40+08:00（运行前）

## 1. 依据（C14 的结论）

C14 证明：即使工具清单可见，agent 仍 **0 次** 调用 `search_code`，而 `list_dir` 用了 **28 次**。
默认策略是"目录遍历 + 分段读"，在 1436 行文件上必然失败。
**Level B 成功，是因为任务文本点名了文件——等于替它完成了搜索。**

## 2. 可证伪命题

**H3**：若失败证据**自带定位**（运行失败时直接返回失败涉及的文件与代码区域），
agent 无需搜索即可定位并修复；无提示任务（同 C′ 文本）将 **PASS**。

**H0**：即使给了定位区域，agent 仍不编辑或不修复 → 瓶颈不在定位信息，而在**修改决策**。

## 3. 唯一改动（相对 C′）

`W5SourceExecution.run_execution()` 的返回值中，`tail` 增加一个 **`suspect_regions`** 字段：

- 由**失败证据**推导，不是人工标注答案：
  从 FSM trace / detail 中解析**失败的阶段**（如 `PLACE_B`）与**对象**（如 `target_box_b`），
  再到源码中检索**与"place 目标 zone"相关的赋值行**，返回 `文件:行号` 列表（最多 5 条）；
- **不**说明哪一行是错的，**不**给出正确写法，**不**指出修改方向；
- 任务文本与 C′ **逐字相同**（含"先运行场景"）。

这是"改变信息获取界面"，不是"加提示"——它等价于把一个更好的调试器输出交给 agent。
