# Self-Evolving Agentic Robotics — 目标拆解

> 一句话：让 AI 不仅**开发**和**控制**机器人，还能通过真实执行反馈**持续学习、改进与扩展**机器人的能力。
> 闭环：Human Intent → Autonomous Development → Autonomous Execution → Verification → Self-Improvement。

## 0. 定位（避免再次做窄）

| 角色 | 是什么 | 不是什么 |
| --- | --- | --- |
| **FlexCell** | 验证愿景的**机器人执行平台/实验台** | 不是终极产品 |
| **Nexent** | 承载决策与进化能力的 **Agent Harness** | 不是研究对象本身 |
| ROS 2 / Gazebo / MoveIt 2 / OpenMANIPULATOR-X | **实现手段** | 不构成研究边界 |

**三条不可让渡的边界**
1. Agent 决定 **WHAT**（做什么、选哪个技能、下一步）。
2. 确定性执行器决定 **HOW**（规划、轨迹、控制、硬件）。
3. 独立验证器决定 **WHETHER**（任务是否真正完成）——**执行成功 ≠ 任务成功**。

反模式：让大模型直接控制关节；把 skill `outcome=0` 当任务成功；为跑通一次而改验证器/阈值/证据。

## 1. 能力阶梯（L1 → L3）

| 层 | 能力 | 可验收判据（示例） |
| --- | --- | --- |
| **L1 开发** | Agent 能开发、部署、调试机器人程序 | 从自然语言需求出发，自动产出可运行的 skill/配置；自动跑测试并依据日志修复，直到通过既定的离线+仿真门 |
| **L2 运行** | Agent 理解任务、自主组合技能、控制机器人完成 | 新任务给出自然语言 → 选中/组合技能 → 执行 → 独立验证通过；异常可按预算恢复 |
| **L3 进化** | 依据执行经验改进技能与策略，跨任务/场景/硬件适应 | 失败被结构化归因 → 产出改进（技能参数/组合/策略）→ 回归不退化 → 新任务/新布局/新适配器上迁移成本可度量地下降 |

当前所处：**L2 的骨架已具备**（决策层、技能契约、独立验证、证据化、仿真执行），**L1 只有人工闭环**（人写代码、人看日志修），**L3 基本未开始**（有失败分类与 TransferBench 的度量雏形，无自动改进闭环）。

## 2. 系统闭环（要打通的五个环）

```
Human Intent
   ↓
Development Agent  ── 写/改 skills、配置、规划流程；测试、调试、发布
   ↓
Runtime Agent      ── 理解任务、感知状态、选/组合 skills、决策与恢复
   ↓
Execution & Verification ── 确定性执行 + 独立验证（WHAT/HOW/WHETHER 分离）
   ↓
Experience & Feedback ── episode/decision/evidence → 失败归因 → 改进需求
   ↓
（回到 Development Agent，迭代下一版本）
```

## 3. 研究问题 → 可验证命题（hypothesis）

| 编号 | 研究问题 | 可证伪命题（示例） | 主要指标 |
| --- | --- | --- | --- |
| Q1 | Agent 如何获得**机器人开发能力**？ | 给定需求规格与现有技能库，Dev-Agent 能在 ≤N 次迭代内产出通过离线+仿真门的改动 | 首次通过率、迭代次数、回归破坏数 |
| Q2 | Agent 如何获得**可靠操作能力**？ | 分层（WHAT/HOW/WHETHER）+ 证据化，使失败可定位、恢复可预算 | 任务验证通过率、恢复成功率、误报成功数 |
| Q3 | 如何**自主组合与扩展技能**？ | 以技能契约为界，组合（composite）可在不改执行器的情况下扩展任务族 | 新任务所需新代码量、组合成功率 |
| Q4 | 如何建立**真实、可重复的执行反馈**？ | 指纹+证据+回放使同一输入可复跑并给出相同判定 | 复现一致率、证据完整率 |
| Q5 | 如何**跨任务/场景/硬件迁移**？ | 迁移成本可分解为参数/对象/组合/恢复/平台五轴并显著低于重写 | TransferBench 五轴成本、适配器代码量 |
| Q6 | 如何**通过经验持续改进**？ | 结构化失败归因 → 改进提案 → 回归门，能带来净增益且不退化 | 改进采纳率、净增益、回归率 |

## 4. 工作包（Workstreams）

| 编号 | 工作包 | 目标产物 | 验收 | 现状 |
| --- | --- | --- | --- | --- |
| **W1** | Dev-Agent 闭环 | 需求规格 schema + 生成/修补循环 + 自动跑门 + 证据驱动修复 | 从规格自动产出改动并通过既定门，记录迭代轨迹 | 无（人工闭环） |
| **W2** | 技能契约与组合 | 统一 skill contract、composite 编排、pause/resume | 组合任务通过独立验证；暂停/恢复有回执 | 契约/组合已有；pause/resume 未端到端验收 |
| **W3** | Runtime Agent | 决策策略路由、恢复预算、验证器接入 | 新任务自然语言→验证通过；异常按预算恢复 | 已有 FSM/Jev/LLM/Hybrid 骨架与验证 |
| **W4** | 证据与可复现 | episode/decision/evidence + 指纹 + 回放 | 同输入可复跑、判定一致、证据完整 | 已具备并用于 CI |
| **W5** | 经验与改进 | 失败分类→改进提案→回归门 | 提案被验证带来净增益且无回归 | 雏形（failure codes、TransferBench），无闭环 |
| **W6** | 跨场景迁移 | T1–T4 实验协议与成本度量 | 五轴成本可测、可比较 | TransferBench 设计已有，T1/T3 试点 |
| **W7** | 跨硬件迁移 | 硬件适配层（skill contract 不变）+ T5 | 换平台仅改适配器，技能/任务/验证不变 | 未开始 |
| **W8** | 评估与基准 | 冻结协议、n 统计、公平比较、门槛 | 可重复的评估报告 | 部分（协议/窗口/证据）；n≥50 冻结 |

## 5. 里程碑与门（Gates）

| 里程碑 | 内容 | 门（必须同时满足） |
| --- | --- | --- |
| **M0 平台可信**（当前） | 确定性执行 + 独立验证 + 证据化 + CI | 核心窗口功能通过；证据可复跑；失败不静默 |
| **M1 L1 开发闭环** | Dev-Agent 能改代码并自证 | 规格→改动→门通过，≥3 类需求（新技能/参数/组合）各 ≥1 次；回归 0 |
| **M2 L2 运行闭环** | Runtime Agent 端到端 | 新任务自然语言→验证通过 ≥N 次；恢复预算生效；误报成功 0 |
| **M3 L3 进化闭环** | 经验→改进→迁移 | 失败归因→提案→净增益；跨布局/跨平台迁移成本下降有数据 |

> 说明：n 的统计门槛按既有冻结策略执行，不因叙事需要提前解冻。

## 6. 指标字典（先定义，再谈提升）

- **任务验证通过率**：独立验证通过 / 派发任务数（不是 skill outcome）。
- **误报成功数**：执行返回成功但验证不通过（必须为 0）。
- **恢复成功率**：预算内恢复成功 / 触发恢复次数。
- **首次通过率 / 迭代次数**（L1）：Dev-Agent 第一次提交即过门的比例与平均迭代。
- **迁移成本**（L3）：五轴（参数/对象/组合/恢复/平台）的人工改动量、代码行、调试时长。
- **净增益**（L3）：改进前后同一评估集上的通过率差，减去回归损失。
- **复现一致率**：同输入重跑判定一致的比例。

## 7. 近期冲刺（两周切片，按依赖排序）

1. **W2 收尾**：composite 暂停/恢复端到端验收（有 checkpoint 代码，缺真实验证）。
2. **W4 强化**：把"证据→可读报告"标准化（一次运行产出人类可读的失败归因摘要）。
3. **W1 最小闭环**：需求规格 schema + "改一个技能参数/新增一个组合"的两类自动任务，先跑通"生成→门→证据→修复"一次。
4. **W5 雏形**：失败分类 → 改进提案模板（人审），先不改代码，只产出可执行提案。
5. **W8 对齐**：把上述门的通过/失败记录进统一评估报告，避免口径漂移。

## 8. 风险与反模式

- **再次做窄**：把时间全花在 Gazebo/MoveIt 调参，忘记 L1/L3 闭环。
- **叙事先行**：没有自动闭环就宣称"自进化"。
- **指标污染**：用 skill outcome 替代任务验证；用单次演示替代统计。
- **越权控制**：让 LLM 直接下发关节/轨迹。
- **证据污染**：为通过而改阈值/验证器/回执。

## 9. 与仓库的映射

| 层 | 现有资产 | 缺口 |
| --- | --- | --- |
| 开发（L1） | 技能/配置/launch、CI 门、证据 | 规格 schema、自动生成/修补循环、迭代轨迹 |
| 运行（L2） | 决策策略、技能契约、composite、独立验证、恢复预算 | pause/resume 验收、长任务稳定性 |
| 证据（W4） | episode/decision/evidence、指纹、回放、对账 | 人类可读归因报告 |
| 迁移（W6/W7） | TransferBench 设计、T1/T3 试点、组合能力 | 五轴成本自动化、硬件适配层 |
| 进化（L3） | 失败码、恢复配方、协议/窗口 | 归因→提案→回归的自动闭环 |

## 10. 结论

FlexCell 的工程细节（ROS 2/Gazebo/MoveIt/skills）是**手段与实验环境**；项目的核心研究对象是**Agent 如何获得开发、操作、验证与进化机器人能力**。
后续每个 PR 应能回答：它推进了上面哪一个工作包、哪一个研究问题、哪一个门。
