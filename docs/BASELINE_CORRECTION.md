# 基线对照的修正：我原来的 Baseline A 是不公平的

**日期：** 2026-11-11 00:55 (+08:00)

## 我发现的自己的错误

我最初的 Baseline A（`plan_from_spec`）**直接读 `expected_goal`** 来生成阶段计划：

```python
placement = dict(spec["expected_goal"].get("placement") or {})
```

这意味着 A 是一个**开了答案的预言机**——它只会在执行环节失败，永远不会在规划环节失败。

那么「A 通过、B 通过」这个比较实际上测的是**执行可靠性**，
而不是我声称要测的**规划能力**。这是设计缺陷，不是结果。

## 修正：Baseline A′ —— 确定性规则规划器

`experiments/baselines/baseline_a_prime_rules.py`

A′ 与 B 拿到**完全相同的输入**：指令、能看到的物体、能用的箱子。无 LLM。
用固定正则和几何规则解析指令。**解析不了的就承认解析不了**（抛 `Unparsed`）。

### A′ 的规则覆盖

| 模板 | A′ 能解？ | 用到的规则 |
| --- | --- | --- |
| T01 排序 | 能 | `the <color> block in the <side> bin` |
| T02 排除 | 能 | `except the <color> block` + `clear the table` |
| T04 几何区分 | 能 | `FURTHER from the robot base` + hypot |
| T05 中转 | **不能** | 规则引擎没有「中途停一次」的概念 |

## 诚实的结论：当前模板区分不出 Agent 与规则

**A′（无 LLM）成功解出 T01、T02、T04。**

所以在这三个模板上，「Agent 能完成」并不能说明 Agent 有规划能力——
**一个几十行的正则引擎也能完成**。

这不是失败，这是**测量结果**：说明 v0.1 的任务太容易，无法区分两臂。

## 什么模板才可能区分

要区分 Agent 与规则引擎，任务需要**规则无法穷举的推理**：

1. **T05 中转** —— A′ 明确解不了。需要「先放这里，再拿起来放那里」的多阶段状态；
2. **需要根据观测调整的任务** —— 例如指令与实际情况不符（目标箱被占），要求重规划；
3. **组合条件** —— 「除了红色之外，把离机器人最近的放到…」；
4. **失败后恢复** —— 抓取失败后换策略（这是 Level 3，本轮完全没测）。

T05 是**最直接**的下一步：已知 A′ 解不了，如果 B 能解，那就是真实的区分证据。

## 对之前报告的影响

| 之前说的 | 现在应该说 |
| --- | --- |
| 「T01 两臂都 PASS」 | T01 上 A′ 与 B 都能解，**无区分力** |
| 「T02 两臂都 PASS」 | 同上，**无区分力** |
| 「T04 是唯一可能区分 A/B 的」 | **也错了**，A′ 用 hypot 就能解 |
| 「Baseline A 测的是栈的能力」 | A 实际是预言机；**A′ 才是公平基线** |

## 修复的 T04 任务缺陷（独立问题）

原 T04 的指令与 `expected_goal` **完全相反**：

```
指令：further(0.269) → right bin(zone_1)
目标：target_box_a(0.220) → zone_1     ← 矛盾
```

**照指令正确执行的 Agent 必然被判 FAIL。** 而且它还谎称「两个方块看起来一样」，
而它们其实是红和蓝。

已修：placement 现在由**指令陈述的同一规则**计算；新增 2 个一致性测试。
