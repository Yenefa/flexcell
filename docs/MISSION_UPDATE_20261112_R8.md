## §19.1 本轮：一个关于能力的假设，以及它被自己推翻

第 3–5 轮发现了两处同形的缺陷：**技能内部的精度契约被当作二值成功判决，而世界其实已经满足了任务**
（`place` 用夹爪孔径判断释放，而承载层已确认释放）。

于是显而易见的问题：**T08 的 0/6 是不是同一回事？**

值得问，因为之前两次 held-out 通过恰恰来自**技能自己拒绝掉**的运动（`ec=36`、`ec=28`）。

## §19.2 我第一次的判断是「是」，而它是错的

我先按位移区间、垂直上界、方向余弦三项给 23 条 push 记录打分：

```
独立满足判据的记录 ：8 / 23
  ...其中技能判为失败 ：6
```

75% 的假拒绝率，看起来是一个重大发现。

**我漏了一个子句。** `benchmark/evaluators/evaluate.py:199-210`：

```python
if want.get("zone"):
    d = _dist2d(end, zones[zn]["pose"])
    zone_ok = d <= zones[zn]["radius"]
```

任务要求物块**最终停在 `zone_push` 内**（半径 0.06 m）。我在找这个错误类别的时候，自己走进去了一次。

## §19.4 唯一一处假拒绝是真的，而且同形

`U/seed3002`：物块沿要求方向移动 **0.1480 m**（任务区间上限 0.150），停在距区心 **0.0294 m**（半径内），
未抬起（dz 0.0028）。**任务已满足。**

技能报 `ERR_DISPLACEMENT_OVERSHOOT`，因为它**请求 0.0900 m** 而实际移动 0.1480 ——
误差 0.0580 对 `displacement_tolerance_m` = **0.005**。

| 判据 | 接受什么 |
| --- | --- |
| 任务的冻结 push 子句 | 位移落在 **[0.030, 0.150]** **且**在区内 |
| 技能自己的判决 | 位移在**请求值 ±0.005 m** 内 |

**技能比任务严格 12 倍，而且量的不是同一个东西**（距请求值，而非区间归属）。

同形第三例：

| # | 技能 | 内部契约 | 任务现实 |
| --- | --- | --- | --- |
| 1 | T08 push 门（第 2 轮） | 孔径行程 = 抓到 | 与空气相差 0.42 mm |
| 2 | `place` 释放（第 3–4 轮） | 孔径 = 已释放 | 承载层已确认释放 |
| 3 | T08 push 判决（本轮） | 距**请求值** ±5 mm | 任务接受一个**区间** |

**但幅度很小，我必须说准：1/7，不是 6/7。** 前两处是系统性的（37.5% 的 run；100% 的 place 失败）。
修好这一处，T08 从「0/7 技能自证」变成「1/7」，不是变成 6/7。

## §19.6 这改变了什么

- **T08 仍是真实能力缺口**：物块需要移动约 0.09–0.11 m 才进区，实测只到 0.014–0.051 m。
- **卡点是到达距离，不是验证**。验证层没有在制造失败。
- **超调规则值得单独复查**，但它是本轮唯一找到的假拒绝，**不是**这个项目与 T08 之间的障碍。
- **真正的目标是位移**，而这正是高度标定暴露的同一接触几何问题——**改判决修不了它**。
