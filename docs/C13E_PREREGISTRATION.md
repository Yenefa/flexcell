# C13e 预注册 — 让撤回从实测状态重新规划

**写于改代码之前。只允许一次尝试；不成立立即回退。**

## 1. 已确立的根因（C13d）

`place_server.py:309` 一次规划 `[hover, descend, retreat]`。
第 3 阶段（撤回）的起点是第 2 阶段的**预测终点**，
而下降+释放后实测偏差 **0.0529 rad**，超过守卫的 0.03 rad 容差，撤回被拒。

## 2. 可证伪命题

**H1**：若把规划拆成「先 `[hover, descend]`，执行完再单独规划 `retreat`」，
则撤回的起点来自**实测**状态，守卫可通过，MTC **完成** `dual_object`。

**H0**：拆分后 MTC 仍失败 → 预测偏差不是唯一原因，我的 C13d 归因不完整。

## 3. 修改范围

只改 `place_server.py` 的 MTC 分支：
- 原：一次 `mtc.prepare(..., [hover, descend, retreat], ...)`
- 新：先 `mtc.prepare(..., [hover, descend], ...)`，执行完 hover+descend+release 后
  再 `mtc.prepare(..., [retreat], ...)`

**不动**：守卫容差（仍 0.03）、验收器、任何阈值、其他 skill。

## 4. 明确不做的
- 不调大 0.03 rad；
- 不改 `_consume_mtc` 的判定逻辑；
- 不加"跳过第 N 阶段检查"之类的特例。

## 5. 判定

| 结果 | 判定 |
| --- | --- |
| MTC PASS `dual_object` | **H1 成立** → Track C 否定结论**撤回**，MTC 确实能完成受约束场景 |
| MTC 仍失败但错误不同 | **H0** → C13d 归因不完整，记录新错误 |
| legacy 或默认世界出现回归 | **立即回退**，本次改为负结果 |
