## 顺序、donor 与历史台账

默认计划仍读取 RUN_MANIFEST 的24个登记槽位；新重复须先提供显式版本化 JSON：

```json
{
  "schema": "evobot.dispatch_plan/1",
  "plan_id": "NEW_VERSION_TO_PREREGISTER",
  "slots": [
    {"slot_id": "F1-B-r2", "seed": 5102},
    {"slot_id": "F1-C-r1", "seed": 5101, "donor_run_id": "F1-B-r2"}
  ]
}
```

该示例只说明格式，不是已经准入的研究方案。原登记 C-r1 早于其 B-r2 donor，
本修补保留这个依赖缺口并产生 NOT_RUN，不临时换来源；下一轮完整实验需先修订并登记计划。

RUN_MANIFEST 状态明确绑定 v2 主批次 r1–r3，而不是 v1；额外24槽与历史顺序偏差分别报告。
对账默认因顺序不匹配失败；查看已登记的历史偏差时才显式指定：

```bash
python3 experiments/repair_eval_v02/reconcile.py \
  --manifest docs/research/evobot-paper-v02/RUN_MANIFEST.md \
  --records experiments/repair_eval_v02/evidence/v2_matrix_n6.json \
  --registered-only --allow-order-deviation
```

输出应同时包含状态 CONSISTENT、顺序 DEVIATION、额外24槽；状态一致不代表协议执行合格。
模型输入尝试、工具访问记录随候选归档，反馈摘要改为首轮实际消息中的执行反馈，
不再对 TASKS 文本做摘要。`message_attempts.json` 包含预算门拒绝前构造的尝试，不能当付费调用数。
