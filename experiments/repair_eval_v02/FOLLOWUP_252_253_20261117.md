## 停止与证据

运行前、运行后都核对源码提交和文件摘要、依赖、工作区存在性及受保护文件。
执行终态独立记录为 `SUCCESS`、`TYPED_FAILURE`、`TIMEOUT`、`NO_RESPONSE`；后两项停止整批。
健康失败记 `INVALID`，动作未确认记 `UNKNOWN`，所有后续槽位写 `NOT_RUN`。
独立门未运行造成的 `UNKNOWN` 与动作无响应分别记录，不能混为一类。

当前 `--source instances` 执行的是封印的源码/配置检查，ROS/Gazebo 检查明确记
`NOT_APPLICABLE`，不能因此声称仿真健康或物理任务成功。`health.probe(backend="gazebo")`
需要调用者提供拥有的进程及就绪探针；它不杀进程，也不自动占用 #247 的窗口。
该分支没有把主批次转换成 Gazebo 执行器。

每个尝试过的槽位保留初始与最终候选、遥测、账本、工具对话、健康结果、异常和最终裁决。
工作目录先写在持久目录，归档复制和逐文件校验成功后才删除原工作目录。
归档失败停止整批并留下 `preserved_workdir`。输出文件、归档、freeze 和评估目录均不能覆盖已有版本。
连续三条预算耗尽按原协议 S3 停整批；单条预算耗尽不升级为成功。

## 冻结与比较入口

先从新主批次结果中的 `row.archive.path` 取得模型最终工作区。不要用旧记录的
`edited_paths`、门判 PASS 或参考修复猜测其内容；旧批次没有保存最终字节，不能从这些字段还原。

以下命令中的路径需替换为实际新归档，输出路径每次用新名称：

```bash
python3 experiments/repair_eval_v02/evaluate_holdout.py reference \
  --instance DEF-F1-REG \
  --source-sha 2ca40ebe6c5e33dcc5d7ecb229d26aa36807ca35 \
  --basis '预先指定的 team-handoff 基线；不依据保留集结果选择' \
  --out /tmp/evobot-reference-f1

python3 experiments/repair_eval_v02/evaluate_holdout.py freeze \
  --candidate-archive /path/to/new-model-batch/slots/F1-B-r1 \
  --reference-archive /tmp/evobot-reference-f1 \
  --selection-basis '按已登记主批次选择规则；在读取本轮保留结果前选定' \
  --reference-basis '固定 team-handoff 基线提交，来源在参考归档中' \
  --repair-runs 24 --out /tmp/evobot-freeze-f1.json

python3 experiments/repair_eval_v02/evaluate_holdout.py evaluate \
  --freeze /tmp/evobot-freeze-f1.json --out /tmp/evobot-evaluation-f1
```

示例中的 `24` 只说明修复运行数单独登记，实际填写主批次的真实数量；F2 同样单独冻结、比较。
`candidate_sha` / `reference_sha` 是候选代码和数据文件清单的 SHA-256；
`candidate_source_sha` / `reference_source_sha` 则是来源 Git 提交，不能互相代替。
freeze 同时锁定评估器、七例数据和来源表的摘要；替换任一输入会被拒绝。

六槽为 `L1/L2 × s1/s2/s3`，每槽分别记录候选与参考结果、编辑摘要与原始证据位置。
执行只重放归档中已经存在的变更，不再调用模型或参考修复。无法唯一适用的变更记失败。
F1 不允许删掉或改写保留布局坐标。回归中的负例预期被拒绝；拒绝正确才是该回归 `PASS`。
缺失案例、异常、错误接纳、错误拒绝、理由码不匹配均保留为 `FAIL`，不跳过余下案例。

**证据边界：**当前六槽只执行源码/配置检查。三个初态仍是标签，F2 不执行布局几何；
`state_coverage`、`ordinary_task_regression=NOT_RUN`、`gate_independent=NOT_RUN` 和
`admission_status=NOT_VERIFIED_PHYSICALLY` 必须随报告保留。结果只能说明这套有限检查，
不能外推跨本体、真机或物理泛化，也不能用来把 #253 整体勾为完成。
要关闭原 issue，还需拿主批次选定的真实模型归档，结合 #247 入口完成真实初态与普通任务回归。
