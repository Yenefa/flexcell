# P1.3 REPORT — 结合相关工作解释 P1.2 结果

> 目的：用已核实的文献事实解释"为什么执行反馈有效、独立验证不显著"，并修正差异化表述。
> 证据等级：论文原文（arXiv HTML/摘要）+ 我们 27 次运行记录。

## 1. 两项相关工作的核实结果

### RoboForge（arXiv 2610.17881，2026-10-13）
- 原文：agent 生成参考运动与学习目标、训练策略、**检查 rollout**；"Execution therefore serves as a physical verification signal rather than merely the endpoint of learning."
- 失败时区分"请求的行为不对"还是"学习方式不对"，修订运动或奖励并重训。
- 覆盖 4 种机器人 + 真机部署；对照 reward-refinement 与 one-shot motion 基线。
- **关键区别**：它的"verification"是**执行/rollout 信号**（≈我们的 C 臂），**不是**与执行器分离的独立验证器（B 臂）。

### RoboOS（arXiv 2505.03673）
- Brain-Cerebellum 架构：RoboBrain（MLLM 决策）+ Cerebellum Skill Library（即插即用技能）+ Real-Time Shared Memory（多机状态同步）。
- 论文提到 FlagScale 的 TB 级历史数据与"task replay / anomaly backtracking"，但**全文未出现** postcondition、independent verification、evidence 等表述（检索为 0 命中）。
- **判定**：不能宣称它"没有验证"，但可以说"论文未记录技能级后置条件与独立验证机制"；这正是我们的候选差异，且是**文档级差异**而非已证明的能力差异。

## 2. 用它们解释 P1.2

### 2.1 C − A 显著（p=0.0023）与 RoboForge 一致
RoboForge 的核心机制是"执行结果回流到生成/修订"；我们的 C 臂正是这个机制的最小化版本（执行 telemetry → agent 修复）。
→ **"执行反馈有效"不是我们的新发现**，而是与既有工作一致的复现；我们的增量在 **ROS 软件工程层**（真实契约代码、工具权限、证据/哈希、可复现记录）。

### 2.2 B − C 不显著（p=1.0）的可能原因
1. **信息等价**：在单故障任务中，telemetry 的 `EXECUTION_ERROR code=71/72` 已足够定位；verdict 只是同一信息的更整齐版本。
2. **任务单故障**：只有一个失败点，不需要"归因"；B 的结构化后置条件优势无处发挥。
3. **B 的额外成本**：多读一次 verdict 往往多一轮，抵消了信息优势。
4. **唯一正向信号**出现在 T-B（两段链，3/3 vs 2/3）——恰是"需要阶段归因"的任务，符合上述解释。

### 2.3 修正后的主张
| 主张 | 证据 | 状态 |
| --- | --- | --- |
| 执行反馈显著提高开发成功率 | C−A +77.8%，p=0.0023 | **可主张（探索性）** |
| 独立验证带来额外增益 | B−C +11.1%，p=1.0 | **不可主张** |
| 结构化后置条件在多阶段任务上有价值 | T-B 3/3 vs 2/3，n=3 | **假设，待检验** |
| ROS 软件工程层 + 证据化是差异 | 与 RoboForge/RoboOS 的文档对比 | **候选差异，未证明优越** |

## 3. 下一步实验（据此设计，而非拍脑袋）

**B2 臂（诊断级验证）**：在 B 的 verdict 中加入
- `failed_stage`（已有）、`expected_vs_actual`、`suspected_cause`（reach/overshoot/profile）、`suggested_fix`（仅提示，不给答案）。

**任务集 v2**：制造"telemetry 不足以定位"的任务——
- 多阶段且**只有最终位置可观测**（中间阶段日志缺失）；
- 两个候选原因产生相同错误码（如 reach 与 profile 都报 71），需要 B 的归因区分。

预期：若 B2−C 仍为 0，则"独立验证无额外价值"在该任务族上成立；若 >0，则说明价值来自**归因而非判定**。

## 4. 效度与边界

- 所有 P1.2 结果仍是合成执行模型（非 Gazebo），**M3-S 未达成**；
- RoboForge/RoboOS 的事实来自论文文本，代码行为未复现；
- 本报告不改变 P1.2 的任何数字。
