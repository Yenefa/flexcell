# 审计发现：提案目录是空的 —— C 永远无法改进自己

## 我做的第一件事是审计，不是加功能

使命要求「通过完成任务获得能力，而不是预先写死修复」。但最近几轮**全是我在手工改代码**。
于是我审计了自进化模块：

```
evolution/experience/   存经验（有 4 条）
evolution/diagnosis/    分类失败（10 类）
evolution/validation/   回归门（有 gate()）
evolution/proposals/    ← 空目录
evolution/transfer/     ← 空目录
```

## 这解释了持续两轮的负面结果

**回归门能判定提案，但没有任何东西产生提案。**
所以提案永远不会被接受，C 永远不会改变自己——
这正是两轮 B/C 实验测得「经验 0 效果」的机制原因。

**到不了行为的「学习」不是学习。**

## 补上这条链

新增 `evolution/proposals/generate.py`：

| 规则 | 说明 |
| --- | --- |
| 只读实测证据 | 从归档 `task.out` 读，**不读验收判决** |
| 按可观测签名聚类 | 不猜原因 |
| 最少 2 次才提案 | 单次失败不够 |
| 不得触碰受保护路径 | 由门禁二次校验 |
| 必须给出可falsify的预期效果与回滚 | 门禁要求 |
| **绝不修改源码** | 应用是独立的人工批准步骤 |

## 实跑结果

扫描全部归档，实测失败 24 次：
```
SKIP  unconfirmed            n=19  no evidence-backed change for unconfirmed yet
GATE  occupied_destination   n=5   ACCEPTED
```

`occupied_destination.json` 提案被门禁接受，写明 `requires_human_approval: true`。

## 但我必须自己打假：这个提案是「事后重建」

我写了 `check_applied.py`：**用真实代码行为验证提案**，而不是读文字描述。
它重建归档证据里那个失败场景，问当前代码会不会还失败：

```
occupied_destination.json  ALREADY_SATISFIED
  最近距避让物 0.081 m，间距 0.090 m
```

**`ALREADY_SATISFIED` 意味着：间距我早已手工修好，提案只是把既成事实重新推导一遍。**

这**不是**「系统自己发现并修复了问题」。如果我把这写成自进化成果，就是造假。
所以标签是**计算出来的**，不是写上去的：

| 标签 | 含义 |
| --- | --- |
| `ALREADY_SATISFIED` | 当前代码已能处理，提案是事后重建 |
| `WOULD_FIX` | 当前代码仍失败，提案是真正的修复 |
| `REFUSED` | 代码明确拒绝该场景 |

## 剩下 19 例：生成器诚实拒绝

全是 `err 62` 抓放失败（`PLACE_A:FAIL`）。
**没有任何可计算证据支持某个具体代码改动**——
唯一诚实的回答是「我还不知道该怎么改」，而不是编一个改动让它看起来能自愈。
