# EvoBot v0.2 — 未见任务类型上的首次测量（headroom 出现）

## 为什么做这个实验

上一轮 B/C 配对得到负面结果：v0.1 held-out 上 B **6/6 全过**，
**天花板附近测不出经验的效果**。要测出差异，必须有 Agent 会失败的任务。

按使命的 Level 8 方向，新增**两类从未训练过的任务类型**（独立模块，
不改动已冻结的 v0.1，也不改验收器容差）：

| 模板 | 考什么 |
| --- | --- |
| `T12_triple_revisit` | 三步长程状态跟踪：`右→左→右`，必须真的访问三次 |
| `T13_geometric_conditional` | 按**实测距离比较**分支决定两个物体的目标箱 |

两类都只用现有 pick/place/verify 与 2 箱 2 物体场景，
**不注入缺陷、不新增技能、不放宽任何阈值**。
规则引擎 A′ 对两类**都无法求解**（有单测断言）。

## 结果（6 个未见 held-out，封存答案 + 隔离 UID）

| 指标 | 值 |
| --- | --- |
| **Agent 规划正确** | **6/6**（逐条与封存答案核对） |
| 独立验收 PASS | **4/6 = 67%** |
| 干净 PASS | **3/6** |
| 分歧 PASS（执行器报失败但物理目标达成） | 1/6 |
| 判分失败 | 2/6 |
| **False Success Rate** | **0/6 = 0.0%** |

**对照 v0.1：B 6/6 → v0.2 未见类型 3/6 干净通过。Headroom 出现了。**

## 最有价值的发现：所有失败都在执行层

6 个 Agent 计划**全部正确**，但只有 3 个干净完成：

| 失败 | 执行器错误 | 归因 |
| --- | --- | --- |
| T13 | `err 61 state drift or occupied destination` | 同箱两物体落点冲突 |
| T12 | `err 62` 第三步未完成 | 长程链在末段失败，`visits` 只到 `[zone_1, zone_2]` |
| T13 | `err 62` 但实测落位正确 | **执行器/验收器分歧**（与上轮 T03 同类） |

这意味着：**瓶颈不在「Agent 会不会规划」，而在「机器人能不能可靠执行长链」。**
这个结论和直觉相反——我原本以为未见类型会难住规划。

## 新增的判分能力：有序访问

T12 若只用集合式 `visit`，两步 `zone_2→zone_1` 也会通过，
**无法证明真的走了三步**。新增 `visit_sequence` 子句：
```
required = [zone_1, zone_2, zone_1]
observed = [zone_1, zone_2]  ->  FAIL
```
这是**更严格**的新子句，不是放宽。单测覆盖「两步捷径必须判 FAIL」。

## 封存隔离

- 6 个公开任务在 `benchmark/held_out/unseen_public/`，零答案字段；
- 答案在 `/etc/evobot/sealed/`，root:root 600；
- Agent 在 uid 1001 规划，批次后复验 `BLOCKED_GOOD`；
- v0.1 的封存集**未被触碰**。

## 可以宣称 / 不能宣称

✅ **Agent 在未见任务类型上规划 6/6 正确**（Level 8 的规划侧证据）
✅ 首次在**未见类型**上得到可测量的失败率，给经验迁移留出空间
✅ False Success Rate 0.0%

❌ **不宣称 Level 8 达成**：完成率只有 3/6 干净，n=6 太小
❌ 不宣称经验迁移有效（本轮 C 未跑）
❌ 1 例执行器/验收器分歧仍未解决
