# 我推翻了自己上轮的提案措辞，并预注册了验收标准

## 上轮我写了什么

> 「仅因首次 stall 失败的阶段**会成功**」

这轮量化后发现：**这句话是空的**——那些阶段**本来就会成功**。

## 第一步：先量出基准率

9 个出现过 stall 的运行：

| 结局 | 数量 |
| --- | --- |
| 后续执行中自行解决 | **6** |
| 持续 stall（再次卡死） | **3** |

基准率 **67%（Wilson 95%: 35–88%）**——注意区间很宽。

## 第二步：这 6 例是谁救回来的？

| 谁解决的 | 数量 |
| --- | --- |
| **我现有的计划级重试**（B 失败 → R 通过） | **4** |
| composite 运行内自行吸收（B 本就通过） | 2 |
| 始终未解决 | 3 |

**现有机制已经救回 6/9 = 67%。**

而技能层重试的理论上限**也正好是 67%**——
**两者是同一批案例。**

## 所以我的提案措辞必须改

| 项 | 上轮（错） | 本轮（对） |
| --- | --- | --- |
| 预期效果 | 那些阶段会成功 | **最终通过率预期不变（29/32）** |
| 真实增量 | 隐含「通过率提升」 | **延迟与风险，不是通过率** |

为什么是延迟与风险：
- 现在一次 stall 的代价是**整段重跑**（实测中位 **13.0 s**，还要重新抓取箱子）；
- 技能层重试只需**重发一次 open**（远低于此），且不必重新抓取。

已把 `expected_effect` 改写为可 falsify 的版本，并新增字段：
```
"increment_is": "latency and risk, not final pass rate"
```

## 第三步：**在改代码之前**预注册验收标准

这是关键。**改动之后再定标准，什么结果都能说成成功。**

预注册文件 `actuator_stall_preregistration.json`：

```json
"registered_before_change": true,
"baseline": {"n":32,"b_pass":25,"r_pass":29,
             "stalls_absorbed":6,"stalls_persistent":3},
"prediction": {"final_pass_rate":"UNCHANGED at 29/32",
               "first_attempt_pass_rate":"may rise by at most 6",
               "persistent_stalls_still_fail":3}
```

### 成功判据（预先固定）

1. 最终通过数**不得低于 29/32**；
2. 最终通过数**预期持平**——若升高，需要**单独证明**，不得默默接受；
3. **每一个持续 stall 的运行必须仍然失败**；
4. false success 必须仍为 0。

### **推翻判据**（比成功判据更重要）

1. **任一持续 stall 的运行通过** → 说明重试在把真失败变成通过 → **必须回滚**；
2. 最终通过数下降 → 回归 → **必须回滚**；
3. false success 非 0 → **必须回滚**。

## 为什么必须先做这一步

我在这几十轮里犯过太多次同类错误：
domain 公式溢出、DDS 归因错、A′ 预言机、假「未跟踪」、
把 stall 当规划问题。
**每一次都是我对着一个好看的数字下了结论。**
预注册是唯一能约束我自己的机制。
