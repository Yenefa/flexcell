# T08 推程饱和：根因诊断（十类归因）

> **更正（同日）：本文件的十类归因把主因判为 Control，那个判断是错的。**
> 接触高度扫描（`HEIGHT_SWEEP_RESULT.md`）显示首要因素是**接触点位置**：
> 方块中心 0.0175 推得动，默认 0.030 连接触都建立不了（0.59 mm）。
> 本文件保留原始推理与证据，**不删除、不改写**，因为它记录了我在拿到扫描数据前的真实判断。
> 正确的完整结论见文末「更正」一节。

**三次独立测量都停在 30 mm 门之前：**

| 实验 | 接触高度 | 请求距离 | 实测位移 | 结局 |
| --- | --- | --- | --- | --- |
| Step 0 | 0.030 | — | **23.02 mm** | 饱和 |
| 首推 run5 | 0.030 | 90 mm | **28.55 mm** | ERR_CONTACT_LOST |
| 证据 run | 0.030 | — | **23.26 mm** | 饱和 |

## 根因：接触丢失后立即放弃，不重试

`contracts/push.py:485-487`：

```python
stalled   = moved_step < p['increment_floor_m']   # 这步物体没动
pushed    = cumulative >= p['contact_floor_m']    # 之前确实推动过
unfinished= cumulative < distance - tolerance     # 还没到目标
if stalled and pushed and unfinished and index > 1:
    lost_at = index
    break          # ← 立即退出循环
```

**一旦某步推动量低于 `increment_floor_m`（1 mm），整个推动立即终止。**

### 为什么这会造成饱和

增量是均匀插值（`push.py:231`）：

```python
total * (i + 1) / increments
```

5 个增量推 100 mm → 每步约 20 mm。**任何一步丢失，就损失 20 mm 行程。**

实测 28.55 mm ≈ 1.4 步 → 第 2 步就丢失，剩余 3 步从未执行。

## 一个重要的反证

早先一次运行（run4）物体移动了 **71.8 mm**，方向余弦 **−0.999**（完全反向）。

**说明物体完全能被推很远**——那次是末端从侧面撞到，物体被扫出去。

所以「推不动」不是物理不可能，是**受控推接触维持不住**。

## 可行的改进方向（按预期收益排序）

### 1. 接触丢失后重新接近（最高收益，改 Control）

当前：丢失 → `break`。

改为：丢失 → 后退 `approach_clearance_m` → 重新接近 → 继续剩余行程。

**代价**：需要额外的增量预算（当前 `max_increments=10`，实际用 5，有余量）。

**风险**：反复重试可能陷入循环，需要重试上限。

### 2. 减小单步行程（改策略参数）

每步 20 mm 太粗。若每步 5 mm，丢失一步只损失 5 mm，且有更多机会维持接触。

**但**：增量数固定为 5，减小步长意味着总距离缩短，与任务要求矛盾。
需要同时提高 `increments`。

### 3. 接触高度扫描（改感知参数）

0.030 是 Step 0 的单点选择。方块半高 0.0175，中心高度即 0.0175。

0.030 意味着接触点在方块中心**上方 12.5 mm**——可能推到上棱而非面心，容易滑脱。

**这是一个具体可测的假设**：扫 0.020 / 0.025 / 0.030 / 0.035，看哪个推得最远。

---

## 下一步建议

**先做 3（接触高度扫描），因为它最便宜且能证伪**：

- 若某个高度能推到 > 30 mm，说明根因是接触点选择，改参数即可
- 若所有高度都 < 30 mm，说明是策略问题，必须做 1（重试）

**不要先做 1**，因为它更复杂，而 3 可能直接解决。

## 更正：我的十类归因判错了主因

拿到接触高度扫描数据后，上面把 **Control（丢失后不重试）** 判为主因的结论站不住。

### 扫描给出的证据

| 接触高度 | 位移 | 接触建立 |
| --- | --- | --- |
| 0.0175（中心） | 151.14 mm | ✅ |
| 0.0200 | 69.92 mm | ✅ |
| 0.0225 | 6.32 mm | ✅ |
| 0.0300（原默认） | **0.59 mm** | ❌ |

**单调关系**：接触点越高推得越少，到 0.030 干脆连接触都没有。
一个「重试策略」无法修复「末端根本没碰到方块」。

### 但 Control 也不是无辜的

同一高度 0.0200 跑两次：扫描得 69.92 mm，证据运行得 10.40 mm。
差异在**增量执行数 5 vs 3**——第二次第 3 步就丢失接触然后放弃。

所以真实情况是**两个因素叠加**：

1. 接触高度选错（0.030 在方块中心上方 12.5 mm，几乎顶到上棱）→ 这是首要因素
2. 接触丢失后立即放弃（`push.py:485` 的 `break`）→ 这让任何一次滑脱都致命

### 我犯了什么错

**我在只有成功运行数据时，就给出了「主因」的结论。**
十类归因的表格看起来很严谨，但归因所依据的样本里，接触高度一直是被固定在
一个糟糕的值上的——我从没让它变过，却声称排除了它。

mission §9 F 说：「凡是声称根因已确认，必须有能区分替代假说的测量。」
当时我没有能区分「接触点」和「策略」的测量，却写了「主因：Control」。

**能区分二者的测量只有一个：把接触高度变成变量。** 那正是扫描做的事。
