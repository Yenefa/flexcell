# P3 — 预算探针：**Level C 的失败是预算截断，不是能力边界**

## 1. 为什么做这个实验

上一轮更正发现：Level C′ / C14 / P2 三次失败**全部触发 `budget_exceeded`**（40k 上限），
因此"agent 看到证据却不编辑"只是**解释**，不是事实。当时我明确写下：

> 不能断言"再多给预算也修不好"。

这个实验就是去验证那句话。

## 2. 设计（与 Level C′ 唯一差别是预算）

| 项 | Level C′ / C14 | **本实验** |
| --- | --- | --- |
| 任务文本 | 无文件名/行号/方向 | **完全相同** |
| `suspect_regions` | 无 | **无（显式关闭）** |
| 预算 | 40k tokens / 24 轮 | **150k tokens / 40 轮（3.75×）** |

## 3. 结果：**PASS**

| 项 | 值 |
| --- | --- |
| 迭代 / Token | 10 / **48,067（占 150k 的 32%）** |
| `list_dir` | **34** |
| `read_file` | 36 |
| `run_execution` | 10 |
| `edit_file` | **1（正确）** |
| `suspect_regions` 是否出现 | **否**（已断言） |
| 目标 `dual_object` | **PASS** |
| 回归 `normal` / `regrasp` | **PASS / PASS** |
| `claim_success` / `false_success` | false / false |

编辑内容正确：
```diff
-                    zx, zy, zz = zones[zone_of[self._obj_a]]
+                    zx, zy, zz = zones[zone_of[decision.target]]
```

## 4. 这推翻了什么

**推翻**："定位成本是硬约束，无定位时 agent 无法完成"这一归因。

事实是：
- 40k 预算下，它需要 **34 次目录遍历 + 36 次读文件 + 10 次运行**才到达编辑，**在此之前就被截断**；
- 给到 150k 后，**同样的策略在第 10 轮收敛**，只用了 48k（32%）。

所以 **Level C′ / C14 的失败 = 预算截断**，不是"不能诊断"。

## 5. 但 C15 的结论依然成立，且更有价值

| 条件 | 迭代 | Token | 说明 |
| --- | --- | --- | --- |
| 无定位 + 40k | 截断 | 51k–54k | **失败** |
| 无定位 + 150k | 10 | **48,067** | **成功，但花了 34 次 `list_dir`** |
| **有定位 + 40k** | **4–5** | **16,937–23,258** | **成功，`list_dir` = 0** |

**定位信息不是"能不能"的问题，是"成本"的问题**：
它把同一个修复从 10 轮 / 48k / 34 次遍历，降到 4–5 轮 / 17–23k / 0 次遍历。
这才是本轮真正的、可量化且未被推翻的发现。

## 6. 连带影响

- **P2 复用实验（54k，被截断）同样不能用来否定经验复用**——它也是预算截断的牺牲品；
- 下一轮若要检验经验复用，**必须在 150k 预算下重做**，否则测的是预算不是经验。
