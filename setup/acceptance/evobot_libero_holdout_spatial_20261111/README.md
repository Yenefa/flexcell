# 留出检验：0/10 —— 样本内的 3/5 **不泛化**

## 为什么必须做这个检验

上轮按高度选接近方式，在 `libero_object` 上得到 **3/5**（策略各 2/5）。
但**阈值 0.140 m 是在那 5 个样本上选的**，属于拟合。
所以这轮在**从未参与选择**的 `libero_spatial`（10 个任务）上原样重跑，**不做任何调参**。

## 结果

| 套件 | 任务数 | 成功 |
| --- | --- | --- |
| libero_object（样本内，阈值在此选出） | 5 | **3** |
| **libero_spatial（留出，阈值冻结）** | **10** | **0** |

**10 个任务全部选择 `side_x`，全部失败**，释放误差 119.4 – 480.0 mm。

按上轮建立的判据：成功的释放误差 ≤ 10 mm，失败的在 100 mm 量级——
所以这 10 次**不是「放偏了」，而是根本没拿住、被接近动作推飞了**。

## 这否证了什么

| 上轮的说法 | 现在的证据 |
| --- | --- |
| 「按几何选接近方式」是一项能力 | **不是**。它在留出套件上 0/10 |
| 3/5 说明系统变强了 | **不说明**。那是 5 个样本上的拟合 |
| 阈值 0.140 有普遍性 | **未证，且留出结果与它矛盾** |

## 附带的读取适配（必须披露）

`libero_spatial` 的目标写法不同：`(On akita_black_bowl_1 plate_1)`——目标是**另一个物体**，
不是 `_region` 站点。第一轮重跑直接 0 结果（解析器不认这种写法）。
我为它**扩展了解析器**（目标物体 → 取其 body 位姿上方 3 cm）。

**这是看到留出数据之后做的修改，必须说明**：
它改的是「怎么读任务」，**没有改被检验的阈值**；但它确实引入了新的未验证成分。

- 不宣称任何 LIBERO 成绩（两个套件一个是拟合、一个是全败）；

- 不宣称解析器扩展是「修复」（它是在看到留出数据后加的，未经独立验证）。

## 下一步（由这个负面结果决定）

两个套件的物体**几何分布不同**（`libero_object` 是罐头/瓶/盒，`libero_spatial` 是碗/盘）。
说明「用高度阈值选策略」这种一维规则**不可能覆盖形状差异**。
要么用**执行反馈**判断抓取是否成功（我们已有这个检测器：释放误差），
在失败后换策略重试——**这才是「真实任务驱动」的做法**，而不是再拟合一个阈值。
