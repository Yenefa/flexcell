## 但 batch2 出现了一个矛盾信号

```
{ "runs": 16, "b_failed": 0, "recovery_ran": 0, "retried": 2 }
```

**首试全部通过，却发起了 2 次重试。** 我的校验器当时只查了反向
（有失败却无重试），**漏了这一向**。

### 查下去是真问题：技能层谎报失败

```
HO-a69ec651037a:
  skill layer : PLACE_A:FAIL
  verdict     : passed=True, failed_clauses=[]
```

**世界状态满足目标，技能层却说失败。**
这不是 false success，是**反方向的 false failure**——而且它骗过了恢复驱动，
触发了一次**根本不需要的重试**。

## 校验器改为两类，而不是一个「失败」

第一版把一切都判成 `BATCH INVALID`。对这个情况**两个选择都错**：

| 做法 | 后果 |
| --- | --- |
| 判整批无效 | 判决和声明其实**完全健全**，扔掉会掩盖技能层的问题 |
| 判整批干净 | 把一个真实发现从报告里藏起来 |

所以改成：

| 类别 | 含义 | 处理 |
| --- | --- | --- |
| **INVALID** | 必需的步骤没跑 | **禁止报任何数字** |
| **ANOMALY** | 数据健全但有反常事实 | **与数字一起报出** |

顺带修了两个计数缺陷：

1. `recovery_ran` 原来只在首试失败时计数，导致 batch2 报 `0`——
   **实际上恢复在每一例都运行了**；
2. 新增 `retried_after_pass`，专门暴露技能层与世界的分歧。
