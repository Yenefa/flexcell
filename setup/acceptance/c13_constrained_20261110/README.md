# C13 — 受约束世界下的 FSM/MTC 对照：**一个被我自己推翻的结论**

## 0. 结论先说

**在唯一一块尺寸正确的受约束场景里，legacy（FSM 派发）完成了整个任务，MTC 没有。**

所以本轮 Track C 机制问题的答案是**否定**的：
**MTC 没有展示出 FSM 缺失的能力**——至少在这个场景上没有。

## 1. 两次运行（同一 scene，只改了顶板尺寸）

| 顶板 | legacy | MTC | 说明 |
| --- | --- | --- | --- |
| **0.30×0.30 m** | ROBOT_FAILURE（止于 `PLACE_A`） | ROBOT_FAILURE（到 `VERIFY_A`，止于 `PICK_B`） | **我的场景 bug**：板子太大，把 box B 也挡住了 |
| **0.12×0.12 m** | **PASS（6/6 全过）** | ROBOT_FAILURE（止于 `PLACE_B`） | **尺寸正确**，这块才算公平对照 |

两轮内部两臂的 `world_sha256` 各自相同（同一世界），两轮之间世界不同：
- 0.30 m：`2ebf1148…c9aa90`
- 0.12 m：`5c03dcf5…b90b1140`

## 2. 为什么第一次看起来像"MTC 更强"

0.30 m 的板子横跨 0.30 m，而 box B 就在旁边——**它被物理挡住了**。
在这种场景下：
- legacy 在 `PLACE_A` 就失败（板子压得更低，放置路径被挡）；
- MTC 侥幸通过了 `PLACE_A`/`VERIFY_A`，然后在 `PICK_B` 撞墙。

我当时把"MTC 走得比 legacy 远"读成了能力差异。**那是错的**：
两者都撞在同一块板子上，只是 legacy 先撞。**走得远不等于能力更强。**

把板子缩到只覆盖 box A 之后，障碍只针对第一个物体，**legacy 顺利完成 6/6，
MTC 在 `PLACE_B` 失败**。方向完全反转。

## 3. 严格判读

| 问题 | 回答 |
| --- | --- |
| MTC 能在这个受约束场景完成吗 | **不能**（`PLACE_B` 失败） |
| FSM/legacy 能完成吗 | **能**，6/6，29.6 s |
| 所以 MTC 展示了 FSM 缺失的能力吗 | **没有证据，且本次结果相反** |

**边界**：n=1/臂；单一场景；"受约束"只实现为一块静态顶板，
不代表 MTC 在其他类型的约束（多候选、窄通道、动态障碍）上同样不行。

## 4. 这不是"没做成"，是一个有效的负结果

24H 目标写明：MTC 若不能展示 FSM 缺失的能力，**"记录负结果"**。
现在有的正是这个负结果，而且它是**可复现**的：

```bash
bash ci-public-window/scripts/c13_run3.sh    # 两臂，读当前顶板尺寸
bash ci-public-window/scripts/c13_verify.sh  # 断言两次运行与反转
```

`verify.py` **同时断言两轮**：既断言 0.30 m 那轮的"看起来 MTC 更强"，
也断言 0.12 m 那轮的反转。任何人都不能只引用前半段。

## 5. 场景是怎么加的（仍然不破坏冻结物）

`scripts/sim_profile.py` 新增 `constrained_approach` scene（**纯增量**）。
实测默认世界哈希 `f78a469d…bb187` **两次改动后均未变**。
既有 `three_boxes` / `tagged_three_boxes` 路径一行未动；无测试断言 `SCENES` 元组。

## 6. 下一步（若要继续这条线）

受约束世界不足以区分两者时，需要换**约束维度**而不是换尺寸：
1. **多候选规划**：同一目标可由多条路径到达、且其中一条会碰撞 → 看 MTC 是否换路；
2. **窄通道**：保留 FSM 作为对照，两臂跑同一批实例；
3. 若仍无差异，应把 Track C 记为"在本项目场景族中 MTC 无优势"并**收回资源**，
   这比继续堆样本更诚实。
