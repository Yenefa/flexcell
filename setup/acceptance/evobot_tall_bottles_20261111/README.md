## 关于 geom_rbound：明确承认这个公式是错的

Lead 指出：所有 runner 的抓取高度都来自 `geom_xpos ± geom_rbound`，而 `geom_rbound`
是**包围球半径**，不是半高。

**我的 probe 没有沿用这个公式。** 我的抓取高度来自：
- 真实世界 AABB：box 用 8 个旋转角点、mesh 用顶点变换（`geom_aabb()`）；
- 颈部 = 稳定后 z 方向 55% 以上**最窄的 5 mm 层**；
- 携带高度 = 篮沿 + 净空 + (grip_site − 瓶底)，全部实测。

`rbound_extent` 在我的 JSON 里**只保留用于复现 Lead 报的 -0.069..0.117**，
不参与任何抓取决策。verify.py 第 1 节专门验证这一点：rbound 报的 z_lo = **-0.0694**
（桌面以下 7 cm，物理不可能），真实 AABB 稳定后是 **0.0000 … 0.1456**。

## 5. 放置为什么失败：篮子被推走

`raw/release_{2,4}_at_site.json`

| 量 | task 2 | task 4 |
| --- | --- | --- |
| 抓取时篮子 y | 0.26767 | 0.26819 |
| 释放时篮子 y | **0.36432** | **0.35406** |
| 篮子位移 | **+96.8 mm** | **+86.0 mm** |
| 悬垂（grip_site − 物体中心） | -0.1770 m | -0.1777 m |
| contain 判据失败轴 | y（-0.0460） | y（-0.0478） |

瓶子悬在夹爪下方 177 mm，搬运时瓶底比篮沿低，**把篮子沿 +y 推走**。
等夹爪到达区域站点 xy 时，篮子已经不在那里了。物体自身释放 xy 误差只有
**5.8 / 7.9 mm**——不是没对准，是对准了一个已经跑掉的篮子。

这解释了此前"释放误差 373 / 551 mm"：那是落点与**原始**区域的距离，大部分是篮子自己移动造成的。

## 8. 修复内容

1. 稳定：`set_init_state` 后空走 25 步再测量
2. 测量：真实世界 AABB（box 八角点 / mesh 顶点），**不用 geom_rbound**
3. 抓取点：稳定后 z 方向 55% 以上最窄的 5 mm 层 = 颈部；若物体高度 < 2×手掌间隙
   （实测 36.3 mm）则退回真实中点
4. 携带：抬到 篮沿 + 净空 40 mm + (grip_site − 瓶底)
5. 平移：到**实测的**篮子中心，不是区域站点
6. 下降：降到 contain box 的 z 中点减去悬垂量
7. 释放：开爪，等 120 步，读 `env.check_success()`

所有数字来自物体/篮子本身，没有针对这两个任务拟合的常数。
