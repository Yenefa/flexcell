# B/C 配对实验 — 负面结果：经验没有带来可测量的改进

## 实验设计（只差一个变量）

同一 6 个 held-out 实例、同一世界、同一封存答案、同一独立验收器、同一模型。
**唯一差别**：C 额外收到检索到的已验证经验（6/6 都注入了 1 条）。
两臂都在 uid 1001 隔离下规划，封存答案不可读（批次后复验 `BLOCKED_GOOD`）。

## 结果

| 指标 | B | C |
| --- | --- | --- |
| 独立验收 PASS | 6/6 | 6/6 |
| 干净 PASS | 5/6 | 6/6 |
| 平均 tokens | 916 | 841 |
| **计划与 B 相同** | — | **6/6（字节完全相同）** |
| False Success Rate | **0/12 = 0.0%** | |

## 我不把这解读为「C 更强」

看起来 C 干净通过 6/6、B 5/6，token 还少 8%。**但这是错的读法**：

1. **6 对 `plan.json` 字节完全相同** → 经验**没有改变任何计划**；
2. 唯一的 clean 差异在 T03：B `err 62` 执行失败、C `err 0`。
   同一个计划在两次运行中一次成功一次失败，这是**执行层波动**；
3. token 差异也不是经验效果——C 的 prompt 更长（多了 lesson），
   若经验起作用，成本应更可解释，而这里只是模型输出长度波动。

**结论：在这 6 个任务上，经验通道没有产生可测量的效果。**

## 为什么这个负面结果有价值

- 它延续了上一个 track 的 P2 发现：**item ②（Agent 写经验）4 种写法未达成**，
  item ③ 只有在**人为塞入笔记**时才看到 −18% iters / −24.6% tokens。
  这里由机器生成经验并真实检索，仍然**没出现迁移效果**。
- 它说明当前 6 个 held-out 任务**太容易**：B 已 6/6 全过，没有改进空间。
  在天花板附近做对照，测不出差异。
- 检索只命中 1/4 条经验，且命中的是「同箱落点」这类**已被代码修复**的问题，
  对规划决策没有增量信息。

## 修掉的两个真实缺陷

### 1. 经验作用域守卫漏了「答案形」lesson
测试用 `expected_goal says zone_2` 直接穿过守卫。原禁用词只挡
evaluator/tolerance 等**判分机器**，没挡**答案本身**。已补 `expected_goal`、
`placement`、`unmoved`、`put box_`、`to zone_` 等。

### 2. token 用量根本没被记录
`Chat.chat()` 返回带 `tokens` 的 dict，但 planner 把它丢掉了，
导致第一版统计里 token 全是 `None`。**资源成本不记录，预算优势就会伪装成能力优势。**
已把 `usage` 写入 `agent_reply.json`，并用同一版 planner **重跑**两臂以保证公平。

另有统计器 `NameError`（变量写错）与 stub 接口同步问题，均已修。
