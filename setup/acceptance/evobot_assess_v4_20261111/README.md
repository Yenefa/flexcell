# False Success 从 3.1% 修到 0%，且**不是靠悲观换的**

## 上轮撤回留下的三个待修缺陷

1. 缺失声明被当作 `False`（结构上禁止 false success）；
2. 自评看到的是**计划**，却标成 `Plan executed:`；
3. 左右约定缺失。

这轮修的是 2 和 3，并把 1 用**守卫**挡住。

## 四个版本，四次测量

| 版本 | prompt 改动 | false+ | false- | **accuracy** |
| --- | --- | --- | --- | --- |
| v1 | 计划标成 `Plan executed` | **1** | 11 | 20/32 = 62.5% |
| v2 | 命令「只看测量、忽略计划」 | 0 | 15 | 17/32 = 53.1% |
| v3 | 去掉那句过度质疑 | 0 | 16 | 16/32 = 50.0% |
| **v4** | **v3 + 写明机器人坐标系** | **0** | **4** | **28/32 = 87.5%** |

## 我在这轮里错了一次，并抓住了

**v2 达到 false success = 0 时，我差点把它当成修复。**
但 accuracy 从 62.5% 掉到 53.1%——**这是靠「更悲观」换来的零**。
一个用降低判断力换来的零，只是把错误换了个方向。

于是我做了 v3，假设罪魁是「只看测量、忽略计划」那句。
**v3 更糟（50.0%）——假设错了。**

## 真正的根因是我没想到的

读 v3 的错误理由时发现：
```
agent 说: "zone_1 (the left bin)"
但规划器约定: +y = 机器人左侧
zone_1 在 y=-0.15 → 是右侧；zone_2 在 y=+0.05 → 才是左侧
```

**自评 prompt 里根本没有坐标系约定**，而规划器有。
它只能**猜**左右，于是猜反了。16/32 的错误全部来自这一个缺失的事实。

这不是「太严格」，是**缺信息**。补上后：

```
v4 false failure 11 → 4，accuracy 62.5% → 87.5%
```

## 修了什么

```python
# runtime/verifier/self_assess.py
ROBOT_FRAME = "+y is the robot LEFT, -y is the robot RIGHT, +x is forward."
```

- 计划标为 **INTENT ONLY**，明确「不是执行证据」；
- 空 release 列表**显式写出 NONE**，而不是整段省略；
- 在 bins 之前写明坐标系；
- **保留**具体事实，**不**加「只看测量」这类笼统不信任。

## 机制守卫：零必须配高准确率

`honesty_guard.py` 现在记录使用了哪一版自评，测试断言：
- 32 例全部有声明；
- **v1 的 1 例 false success 证据必须仍在磁盘上**（不能悄悄删掉）；
- 若 false success = 0，则 **accuracy 必须 ≥ 80%**——
  否则说明这个零是「买」来的。
