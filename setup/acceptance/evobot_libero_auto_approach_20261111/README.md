# 一个系统会选接近方式了：**3/5**（此前两个固定策略各 2/5）

## 上轮的问题

- `top` 成功集 `{0,1}`（2/5）
- `side_x` 成功集 `{1,3}`（2/5）
- 并集 `{0,1,3}`，但**没有单一策略达到它**

真实任务要求的能力是：**根据物体几何选择接近方式**。

## 这轮的做法

从**测得的物体高度**决定策略：

```
height = z_hi - z_lo   （该 body 所有 geom 的 z 范围）
height <= 0.140 m  -> top
height >  0.140 m  -> side_x
```

阈值与环境无关（不是按任务名查表），**输入只有测量值**。

## 结果

| index | 物体 | 测得高度 | 选择 | 官方成功 | 释放误差 |
| --- | --- | --- | --- | --- | --- |
| 0 | alphabet_soup | 0.132 | top | **True** | 3.9 mm |
| 1 | cream_cheese | 0.096 | top | **True** | 4.3 mm |
| 2 | salad_dressing | 0.186 | side_x | False | 373.0 mm |
| 3 | bbq_sauce | 0.145 | side_x | **True** | 3.7 mm |
| 4 | ketchup | 0.187 | side_x | False | 551.6 mm |

**3/5，由一个系统达成**——上轮的并集第一次被单一策略覆盖。

## 剩下两个失败的诊断（已排除一个假设）

两个最高瓶子（0.186/0.187）的几何范围是 `z_lo = -0.069`，**在桌面以下**，
所以「高度」被夸大了，抓取中点被拉到接近桌面处。

假设：把下界钳到桌面（z=0）应当修好。

**实测：更差**（1/5）。钳制改变了高度→策略选择全被推给 top，而 top 对高瓶本来就失败。
所以**这个假设被否证**，且这个否证比假设本身更有用：

| 变体 | 结果 |
| --- | --- |
| 不钳制 + 按高度选策略 | **3/5** |
| 钳到桌面 + 按高度选策略 | 1/5 |
| side_y（换横向轴） | 2、4 仍失败（504/651mm） |

**三个变体都试过了，说明剩下的失败不是「参数没调对」。**

## 不宣称

- 不宣称 3/5 已足够（两个高瓶仍失败，机制已定位但未修好）；
- 不宣称阈值 0.140 是普适的（它是在 5 个样本上选的，属于**拟合**，必须在新任务上重测）；
- 不宣称这是 LLM 规划的结果——选择规则是确定性的几何规则，**这正是用户要求的强确定性基线**；
- 不宣称可迁移到 libero_object 之外。

## 这条对「Agent 的增量价值在哪」的回答

本轮**没有任何 LLM 参与**：接近方式的选择由一条确定性几何规则完成，达到 3/5。
所以现阶段在 LIBERO 抓取放置上，**增量价值不在 LLM**——这也是为什么必须把它作为基线固定下来，
再去看更复杂的任务族是否需要推理。
