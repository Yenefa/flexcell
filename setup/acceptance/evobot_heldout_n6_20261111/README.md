# EvoBot 首次真实泛化测量（held-out, n=6）

## 这是第一次可以合法报告泛化数字

前九轮我一直写「held-out 隔离未强制，不得报告泛化」。上一轮把它变成了
**可验证的 OS 级隔离**，这一轮才真正跑了。

### 运行时的三层分离

| 层 | UID | 能看到 |
| --- | --- | --- |
| 规划（Agent） | **1001**（无 sudo，读不到 `/etc/evobot/sealed`） | 仅公开任务 |
| 执行（Gazebo） | 1000 | 公开任务 + Agent 计划 |
| 判分 | privileged | 封存答案 + 实测观测 |

批次后复验：uid 1001 仍 `BLOCKED_GOOD`；36 个公开文件零答案字段。

## 结果

| 指标 | 值 |
| --- | --- |
| held-out 实例 | 6 |
| 模板覆盖 | T01 / T02 / T03 / T04 / T06（5 类） |
| 独立验收 PASS | **6/6** |
| **干净 PASS** | **5/6 = 83%** |
| **分歧 PASS** | **1/6** |
| **False Success Rate** | **0/6 = 0.0%** |

### 为什么不是 100%

`HO-13c5efca228e`（T03 顺序）的验收器判 PASS，但**执行器自报失败**：
```
outcome=1 error_code=62 / PLACE_A:FAIL (ERR_PLACE_FAILED)
```
而 Gazebo ground truth 显示两个物体**都落在箱内**、顺序也正确。

验收器按**实测物理状态**判分是它的设计职责，所以我**没有**去改判定；
但按 `PARTIAL ≠ SUCCESS`，这一例**不算干净通过**，单独列为「分歧」。
统计器已加入 `disputed` 分类，防止以后把它悄悄混进成功率。

## 修掉的模板设计缺陷：T03 同箱放置

第一轮 held-out 跑出 5/6，唯一失败就是 T03：
```
CompositeError: declared destination occupied at target_box_a-1
```

**Agent 的规划与封存答案完全一致**（`b→zone_1, a→zone_1`），失败原因是
两个物体被送到**同一个箱子中心**，物理上必然冲突。
这是我在**第 3 轮就发现、却一直没修**的模板缺陷。

修复：新增 `spread_destinations.py`。同箱多阶段时按 ±28mm 沿 x 分配不同落点：
- 中心间距 **56mm** > 清空间距 50mm；
- 每点距箱心 **28mm** < 箱半径 60mm；
- **不改验收器、不改任何容差、不改清空间距**；
- 偏移只从 Agent 自己的计划推导，**不读 expected_goal**，不泄题。

新增 6 个测试（总计 **64 个离线测试**）。修复后 T03 可执行。

## 可以宣称

- **Generalization Tested**：5 类模板、6 个**从未见过的** held-out 实例，
  在**强制隔离**下由 Agent 自主规划并独立验收；
- 干净通过率 **83%**（5/6）；
- False Success Rate **0.0%**。

## 不能宣称

- **n=6 太小**，不能给出置信区间；
- **Level 7/8**：这是一次泛化测量，不是「能力已泛化」的结论；
- **100%**：有 1 例执行器/验收器分歧未解决；
- **Baseline C（自进化）尚不存在**，三臂只剩 A′ 与 B。
