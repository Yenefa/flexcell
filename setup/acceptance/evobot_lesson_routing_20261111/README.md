# 为什么 C 从不改变计划：找到机制，而非继续报「无效果」

## 之前两轮只报了空结果

「B/C 计划字节相同」是**空结果**，不是解释。这轮去找**为什么**。

## 机制一：投递地址错了

agent 计划的真实结构：
```json
{"moves": [{"object": "target_box_a", "zone": "zone_1", "why": "..."}],
 "unmoved": ["target_box_b"], "confidence": "high"}
```
**计划里没有任何落点坐标。** 落点是 `spread_destinations.py` 在计划**之后**算出来的。

所以「两个物体进同一箱需要不同落点」这条教训——
**无论多正确，都不可能在 prompt 里改变计划**。
它描述的是下游代码已负责的事，而且**已经实现了**。

审计 4 条已验证教训：

| 消费者 | 条数 | 该消费者是否已实现 |
| --- | --- | --- |
| `spread_policy`（下游代码） | 1 | **是** |
| `harness`（运行时） | 2 | **是** |
| `planner`（真正能吃教训的） | **1** | 是 |

**只有 1/4 的教训属于 planner prompt。** 其余 3 条投错了地址。

## 机制二：唯一可行动的教训**结构上检索不到**

剩下那条「声明世界中的全部物体」是**通用**教训，
不含 `bin`/`order`/`right` 等任务关键词，
而检索评分要求关键词命中 → **分数恒为 0 → 永远检索不到**。

```
修复前: 'Put both blocks in the right bin...' -> 0 lessons
修复后: 'Put both blocks in the right bin...' -> 1 lesson
```

**经验通道在构造上就是空的**，不是经验无关。

## 修复两处后，做决定性检验

C 现在每任务检索到 **1 条**可行动教训。同 16 个封存实例，只比计划（不起 Gazebo）：

| 指标 | 值 |
| --- | --- |
| 配对数 | 16 |
| **计划字节相同的** | **16/16** |
| 计划不同的 | **0** |
| C 检索到的教训 | 每任务 1 条 |

## 代价：真实但无收益

| 指标 | B | C | 差 |
| --- | --- | --- | --- |
| tokens | 15,024 | 15,400 | **+3%** |
| 秒 | 46 | 44 | −5% |

**经验通道多花 3% token，改变 0/16 个计划。**

## 诚实结论

这条教训是**真的**，但**规划器本来就已经满足它**——
B 每次都正确声明了 `unmoved`。
所以它进入 prompt 只能增加 token，不能改变行为。

**C 与 B 的差异不是「实现问题」，是「当前失败类型不是规划失败」。**
剩余失败全在执行层（抓放 `err 62`），
而执行层的知识**本来就该写进代码**（间距、避障、漂移检测），
那正是前几轮我做的事。

## 一个真实收获

修复让 C 的检索**第一次有内容**。这本身是真实改进：
此前它是「空转」，现在是「有输入但无差异」。两者含义完全不同。
