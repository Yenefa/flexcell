# 多模态输入通路：实测证明，不是文档证明

## 为什么这张卡存在

关于「能不能给 Agent 看图片」，此前只有两类证据：**别人转述的文档链接**，和我**没有验证过的假设**。
两类都不算证据。按 mission §9.F：代码存在、文档写了，都不等于能力存在。

所以做一次直接测试。

## 测试

用 `read_image` 读一张真实的 Gazebo 渲染帧：

```
competition/iyaic-2026/SUBMISSION/evidence/frames/frame_first.png
640×480 PNG，25041 bytes，来源 WSL Gazebo run dbbe6dc49915（见同目录 README）
```

## 结果：确实收到了图像并能描述内容

我对 `frame_first.png` 的描述（未经提示、直接看图）：

- OpenMANIPULATOR-X 悬在画面右上方，夹爪张开朝右，爪上有一个红点
- 下方两个方块：**蓝色**在左侧苔绿椭圆标记上，**粉红色**在右侧浅紫椭圆标记上
- 机械臂在桌面上投下阴影，桌面浅灰

对 `frame_last.png` 的对比：夹爪闭合、红点下移；**两个方块位置未变**。

同目录 `README.md` 说明这些是「一次相机 smoke」的抓取—放置过程帧，**未声称任务成功**。
我的视觉判断（臂动了、物体没动）与该描述一致。

## 因此确认了什么

| 条目 | 从 | 到 |
| --- | --- | --- |
| Harness → 模型的 image content block 通路 | UNVERIFIED | **CONFIRMED（实测）** |
| 能否读取真实仿真相机帧 | UNVERIFIED | **CONFIRMED（实测）** |
| 成本 | — | **0（无 API 花费、无新代码）** |

## 没有确认什么（重要）

| 未证明 | 原因 |
| --- | --- |
| EvoBot 的 **planner 循环**已经会发送图像 | 那是另一段代码，本次没碰 |
| 能判断**毫米级**误差 | 640×480 下辨不出 2 mm |
| 视觉判断的**准确率** | n=1，且无独立 ground truth 对账 |
| 我跑在哪个模型上 | **无法自省自己的模型 ID**；只能说「服务本会话的模型」能收图 |

最后一条尤其要写清楚：如果能收图的是 A 模型，而 EvoBot 生产路径用的是 B 模型，
那条结论**不能平移**。

## 等级判定

**`Implemented + 手工验证`，不是 `Simulation Tested`。**

不能拿这张卡说「EvoBot 已有视觉能力」。它说的是「图像能送到模型眼前」，
而「模型看到图像后能改善机器人任务诊断」——那是另一个实验，还没做。

## 下一步（已明确，未做）

1. 用 `camera:=true` 跑一个实例，抓关键帧
2. 对同一时刻同时记录 ground truth
3. 让视觉判断与 ground truth **对账**，而不是互相信任
4. 无图像 / 有图像配对对照，比较错误归因准确率

## 一个方法论上的自我更正

我此前的多模态审计把「SDK 是否支持 image content block」列为 UNVERIFIED，然后**停止了**——
因为核实它看起来需要文档或付费调用。

实际上一次 `read_image` 就够了，零成本。**我把一个能直接测的问题当成了需要外部信息的问题。**
