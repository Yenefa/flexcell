# 侧向抓取 + 释放校验：两种接近方式**成功的物体不同**

## 上轮点名的两件事，这轮都实现了

1. **侧向接近**（`side_x`）：先水平退开 11cm，降到抓取高度，再横向进入——
   因为直上直下时手指会被高瓶的瓶盖挡住（eef 卡在 0.107，目标 0.024）。
2. **释放前校验**：不再盲目松爪；测量物体相对目标区域轴的偏差，
   超过 5mm 就重新对准，最多 4 次——因为上轮 bbq_sauce 是**搬到了但松爪偏了 3.6cm**。

## 结果（同一批 5 个官方任务）

| index | 物体 | top 模式 | **side_x 模式** | 侧向释放误差 |
| --- | --- | --- | --- | --- |
| 0 | alphabet_soup | **True** | False | 575.4 mm |
| 1 | cream_cheese | **True** | **True** | 4.1 mm |
| 2 | salad_dressing | False | False | 373.0 mm |
| 3 | bbq_sauce | False | **True** | 3.7 mm |
| 4 | ketchup | False | False | 551.6 mm |

### 关键观察：两种方式各自救活了**不同的**物体

- top 成功集：`{0, 1}`
- side_x 成功集：`{1, 3}`
- 并集 `{0, 1, 3}` = **3/5**，但**没有任何单一策略覆盖全部**

**这不是「换个参数就好了」，而是缺一个「根据物体形状选择接近方式」的决策。**

## 释放校验还顺便暴露了失败信号

释放误差在成功的两个任务上是 **4.1mm / 3.7mm**，失败的三个是 **373 / 551 / 575mm**。
差两个数量级——说明失败不是「松爪早了」，而是**夹爪根本没拿住，物体被推飞了**。
这条校验同时是一个可用的**失败检测器**。

## 工程缺陷（如实记录）

第一版把 episode 终止当作 `done` 处理，但 robosuite 在 episode 结束后**拒绝动作并抛异常**，
导致 3 个任务直接崩溃、没有结果。改为「捕获拒绝即视为终止」后 5 个任务全部产出了结果。
**崩溃期间我一度得到「只有 1-2 个成功」的空缺表格，那不是能力结论。**
