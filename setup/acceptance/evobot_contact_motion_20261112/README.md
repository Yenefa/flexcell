# 真实指面 TCP、受约束推进与返回后状态

本轮实现的是一个**隔离的指面推进适配器**。在同一公开开发实例 seed2000、任务专用服务图下，K1 开发验证及预注册的 K2/K3 固定复验均通过完整验收；六次30mm请求均通过未修改的单次判定，并完成可用的返回。现有 PushObject action/server、默认 Runtime 和正式基线没有替换。

本轮新获得的开发能力是：在这个已声明范围内，沿真实手指面片接触，以受约束轨迹完成有界推进，并提供返回后的实测位置及可用状态。它不是未见实例、通用可靠性或自主 L4 的证明。

## 结果：单次推进、返回、整任务分开

| 运行 | 角色 | 单次推进/返回后净位移 mm | 全部动作后最终有符号净位移 mm | 冻结验收 |
| --- | --- | --- | --- | --- |
| K0 | 旧方法对照 | 47.948（超调失败） | 46.097 | 9/9 PASS |
| K1 | 开发验证 | 30.480 / 30.494 | 60.974 | 9/9 PASS |
| K2 | 固定复验 | 30.484 / 30.489 | 60.972 | 9/9 PASS |
| K3 | 固定复验 | 30.486 / 30.489 | 60.975 | 9/9 PASS |

K0 行的47.948是冻结 PushObject 日志中的位移模长；该30mm请求因超调失败，整任务的较宽区间仍通过。K1–K3 行列出各次返回后的有符号 −x 净位移，推进阶段另有六个冻结 judge 的 SUCCEEDED。旧方法最终净位移采用全部动作后的 Gazebo 真值46.097mm；其在线停止快照曾为46.257mm，不把该快照当最终值。

因此，本轮证明了当前实例的单次精度与返回接口，**没有证明整任务成功率优于旧方法**。K1 是开发验证，K2/K3 是其前置门槛通过后执行的固定确认对；没有替换失败样本，也不把早期开发运行混入这对复验。

## 三块实现

- `contact_geometry.py`：从实际仿真 URDF/STL 组合世界、link5、EE、手指与真实三角面片。当前末段两指内侧约42mm，而物体35mm；采用一侧真实指面，约24mm横向偏置及85°俯仰。TCP 来自实际三角面片裁剪，不取包围盒角点。模型哈希及 Apache-2.0 许可证随原始证据保存。
- `contact_motion.py` / `run_contact_push.py`：固定 TCP/俯仰的解析 IK、密集路径、关节限位/速度/加速度、桌面及保护物几何检查、MoveIt 自碰采样检查；通过现有一次性轨迹注册交给 MoveToPose 执行。每段最多4mm，按物体实测进展收尾。冻结的 `push.judge` 直接复用，核心合同不改。
- `contact_receipt.py`：分别报告推进结果、原生接触、运动终态是否已知、返回是否完成、返回后真实位移及 `arm_ready`。JSON 版本 `contact-push-receipt/1` 经 `/flexcell/contact_push_receipt` 发布。六个实际返回凭证均被独立 ROS 消费端及时接受，300ms 后均被拒绝。

纯几何计算在后台工作线程进行，ROS/取消及可用观测在主线程处理。数据暂不可用可等待计算完成；发动作前及实际运动期间仍要求原有严格的新鲜度/帧/关节门禁。接触与位姿按同一原生物理步配对；关节从短历史中选择与物理时间一致且源年龄和接收年龄均不超过250ms的完整实测帧。没有通过放宽阈值掩盖调度问题。

## 独立物理证据

K1–K3 的原生5ms序列无时间步缺项。离线用原生世界 link5 位姿加126mm固定变换重建 TCP，并重新将接触点变换到实际指面片：

- 六次接触的后侧占比和水平法线占比均100%；无其他机械臂表面触碰目标；最大面片距离 **0.050mm**。
- 推进段 TCP 横向/高度合成偏差最大 **0.0092mm**，俯仰偏差最大 **0.0041°**。
- 工具网格最小实测桌面间隙约 **2.000mm**；此值按注册夹爪位置重建，需结合未修改的夹爪门禁和原始关节数据阅读。
- 六次返回后单次净位移 **30.480–30.494mm**；返回损失均为负的小量，未靠正向累加隐藏反向移动。
- 三轮各9/9门禁通过：终点、轨迹、支撑、保护物、不抬升、推动接触、夹爪、不附着、不瞬移。

控制器累计接触计数和独立回放计数的窗口边缘可能相差几个物理步；原始记录和两套计数均保留，面片距离与接触性质可直接复核。原生回放是物理证据，162项单测及7项合成真实ROS协议检查只证明软件行为。

## 运行架构与限制

完整默认服务图下仍出现超过2秒的调度停帧。环境 CPU 配额为2核。本轮生成只裁掉未使用的 pick/place/verify/task_fsm 四个服务的隔离启动副本；Observe、Carry、PushObject、MoveToPose、Gazebo、机器人、控制器、桥和 MoveIt 保留。原始默认启动文件未改。新旧方法 K0–K3 使用同一服务图；此项也是组合处理的一部分，不把单个结果当作独立因果证明。

适配器仍很慢：两次请求共24个执行器目标，控制事件跨度约370/460/427秒；K0 一次请求、6个执行器目标、约35秒即进入较宽任务区域，但单次精度不合格。不能宣称成本或速度改进。

当前只支持已固定模型、直立35mm方块及世界−x方向；工程 CLI 读取 `expected_goal`，不是 Agent 的公开输入实验。它尚未接入 DecisionPolicy/Runtime，也不是新的自定义ROS action。默认全栈资源行为、普通任务释放一致性及未见实例仍未验证；正式 T08 仍为 CALIBRATION_UNSUPPORTED，baseline NOT_PROMOTED，L4 NOT_ACQUIRED，目标 active。

路径结点与中点是筛查近似，未提供任意控制器样条下的连续碰撞证明。最终源码仅修正了这一条注释，Python AST 与执行时完全相同，见 `invariants.json`。World revision 有逐次观测阈值；revision 相同不能证明位姿未变。凭证不预留机械臂；下次规划/发动作仍须重新观测并通过原执行器准入。
