# 实证 false success：声称检查被一个「属于别的任务」的计划骗过

## 起因

上轮我建了一个两条件声称检查（在计划容差内 **且** 在区半径内），
离线测得覆盖 40/64、**40/40 全对**，与 LLM 自评混合后 **64/64**、0 false success。

我仍然拒绝采纳，理由是它**验证「执行是否符合计划」，不验证「计划是否符合指令」**。

**那是推理。这轮把它变成实证。**

## 探测过程：前三次都安全失败，每次都有信息

| 尝试 | 结果 | 学到了什么 |
| --- | --- | --- |
| v1 | heredoc 报错、无 `set -e`，**换区从未发生**，跑的是正确计划 | 一个**静默不做事**的探测，看起来和通过一模一样 |
| v2 | 两个阶段被映射到**同一个位姿** | 执行器因间隙冲突**拒绝**，物体没动 |
| v3 | 手工改过的计划 | 计划准备阶段报 `declared destination occupied`，**根本没启动** |

**后两次是系统的好行为**：它不接受碰撞计划、也不接受自相矛盾的计划。
但也意味着「手改计划」这条路走不通。

## v4：用**别的任务的真实计划**

借用 `HO-128c6a231c34` 的计划（它要放 **zone_1**），
跑在 `HO-0dcde4dc0f5a` 上（它要求 **zone_2**）。
计划**自洽、可执行**，只是对本任务是错的——正是要检验的条件。

## 结果

```
计划目标         : target_box_a [0.075,-0.15]  target_box_b [0.165,-0.15]   (zone_1)
实测世界         : target_box_a [0.075,-0.163] target_box_b [0.170,-0.149]  (zone_1)

独立验收器       : passed=False
                   failed=['placement:target_box_a','placement:target_box_b','order']

两条件声称检查   : True
                   target_box_a zone_1 ok=True
                   target_box_b zone_1 ok=True
                   why='both conditions met for every stage'
```

**这就是 false success。** 检查说「成功」，独立验收器说失败。

## 为什么必然如此

两条件检查然把**被测世界**与**计划**比较：

```
条件 1：物体在计划容差内      → 满足（世界精确跟随了计划）
条件 2：物体在计划所指区的半径内 → 满足（计划说 zone_1，物体在 zone_1）
```

**它没有、也无法访问「这个任务应该放哪个区」。**
计划与指令的一致性只能由**读指令**的一方判断——也就是被我准备替换掉的 LLM。

## 由此确定的事

| 结论 | 状态 |
| --- | --- |
| 两条件检查比之前那版更安全（修好了容差 > 余量的问题） | **成立** |
| 它仍然会产出 false success | **已实证** |
| 混合方案 64/64 的样本内成绩来自「计划全都对」 | **成立** |
| **不能采纳它替代自述** | **已定案** |

## 状态

| 项 | 值 |
| --- | --- |
| 封存 | `BLOCKED_GOOD` |
| 验收器 | **未改** |
| 技能层 | **未改** |
| 自述机制 | **未改**（候选模块未接线） |
| 新增机器人运行 | 4 次（3 次安全失败 + 1 次决定性） |

## 不宣称

- 不宣称当前的 LLM 自述不会出这种错（它 70.3% 准确，19 次 false failure）——
  **但它在方向上是保守的**：从未声称过世界不支持的成功；
- 不宣称「没有任何确定性检查能安全工作」（加上独立计划复核后需重新测）；
- 不宣称 4 次探测代表整个失效空间；
- **未上真机，M0**。

## 这轮的方法学收获

**前三次探测都「通过」或「失败」得像模像样，但没有一次真的测到东西。**
如果不是每次都去核对「世界到底动了没有」，v1 会被当成「检查是安全的」证据。
**探测必须验证自己真的改变了被试对象**，这条要写进纪律。
