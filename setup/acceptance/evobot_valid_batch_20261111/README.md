# 第一个通过结构校验的批次：恢复臂第一次真的运行了

## 前情

上两个批次都**看起来**产出了数字，但：

| 批次 | 实际发生 |
| --- | --- |
| pair48 | 自评没跑 → 声明全缺；恢复没跑 → R 臂是 B 臂改的名字 |

上轮把 4 个运行器合并成 1 个、全程绝对路径、内置校验。
**这轮用那个运行器跑完整批次。**

## 批次校验（先过关，再谈数字）

```
{ "runs": 16, "b_failed": 2, "recovery_ran": 2, "claims": 16, "retried": 2 }
Batch structure OK: every failed first attempt has a recorded recovery decision,
every run carries a measured claim, and the retry mechanism demonstrably fired.
```

三项以前**从未同时成立**：

1. 每次首试失败都留下了恢复决策；
2. 每例都有标记 `measured` 的声明；
3. **重试真的发生了（2 次）**。

## 结果

| arm | 通过 | 95% Wilson CI |
| --- | --- | --- |
| **B**（首试） | **14/16 = 87.5%** | 64.0–96.5% |
| **R**（最终） | **16/16 = 100%** | 80.6–100% |

**配对：gained 2，lost 0。**

| 指标 | 值 |
| --- | --- |
| 重试次数 | 2 |
| **False Success** | **0/16 = 0.0%（0–19.4%）** |
| False Failure | 1/16 = 6.2% |

## 因果证据：增益来自恢复，不是运气

两例都是同一模式：

```
HO-47afdffad81a:
  first attempt: PLACE_A:FAIL
  decision   : action=resume, failure_class=grasp
  reason     : "native place stage failed: [PICK_A:OK, PLACE_A:FAIL]"
  committed  : target_box_b-0, target_box_b-1
  retry      : passed
```

注意决策理由：**「已提交的阶段重放会与实测世界状态矛盾」**——
这是测量驱动的决策，不是预先排好的固定答案。

这也是第一次可以说：**agent 通过完成真实任务获得了能力**，
而不是靠我预先写好的修复。

## 自评：第三次复现

| 批次 | 种子 | 准确率 |
| --- | --- | --- |
| v4 重采 | 7300/7400 | 87.5% |
| 原生批次 | 7500/7600 | 87.5% |

三次在 87.5%–93.8% 区间，**false success 全部为 0**。
区间宽度说明样本仍小，但方向一致。

## 必须克制的地方

1. **R = 16/16 不等于 100%**。CI 下限 80.6%，只有 2 例真正经过恢复；
   其余 14 例首试即过，对 R 没有信息量。
2. **gained=2 是很小的样本**，不能据此断言恢复有效率；
3. 本批与撤回批次**同 16 实例**，但世界是随机重开的，不是严格配对重复；
4. 自评仍有 1 例 false failure（`HO-3bfb9643b7b6`：实际通过却声称失败）。
