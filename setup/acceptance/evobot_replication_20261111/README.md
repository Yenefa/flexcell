# 每一次失败都不可复现：单批次失败数是**运行**的属性，不是实例的

## 问题

我一直把失败数当成**实例的性质**来报（「哪些实例难」）。
如果同一实例在一次运行通过、另一次失败，那这个说法就是错的。

## 数据

两个种子集各跑了两次（只用 **attempt-1 判决**，两轮比的是同一件事）：

| 种子集 | 两次运行 |
| --- | --- |
| 7500/7600 | pair48（仅取 attempt-1；其 R 臂无效，但首试判决有效）与 batch1 |
| 8100/8200 | batch2 与 batch3 |

## 结果

| 类别 | 实例数 |
| --- | --- |
| 两次都通过（STABLE PASS） | **24** |
| **两次都失败（STABLE FAIL）** | **0** |
| **一次通过一次失败（翻转）** | **8** |

**翻转率 25.0%**（8/32）。

### 这是最重要的一句

> **我观测到的每一次失败，在重复运行中都至少有一次通过。**
> **没有一个是「这个实例做不了」。**

## 这意味着什么

| 我以前的说法 | 证据要求改成 |
| --- | --- |
| 「15 例执行失败」 | 15 次**运行**失败，分布于多次抽样 |
| 「B 通过 30/32」 | 一次抽样；**25% 的实例会翻转** |
| 「这些实例更难」 | **无证据**——没有稳定失败的实例 |

**任何只跑一次的 A/B 对照，都无法把效应与这 25% 的噪声分开。**

## 对之前结论的逐项复核

| 结论 | 是否仍成立 | 理由 |
| --- | --- | --- |
| goal_check 消除无意义重试（2→0） | **成立** | 依据是**机制**（目标已达成就不再重试），且逐例核对过被跳过的都是验收器已判通过 |
| goal_check「增益 0→2」 | **不成立** | 增益依赖失败运行，而失败是随机的；不能当作改进证据 |
| 释放 stall 是主要失败模式 | **仍成立但需改述**：是主要**运行**失败模式 |
| false failure 5/48 | 是 48 次运行中的 5 次，非 48 个实例 |

## 这解释了此前一个悬而未决的观察

pair48 失败的 3 例重跑后全部通过，我当时说「失败是瞬时的」。
**现在有了量化：25% 的实例会在两次运行间翻转。**

## 状态

| 项 | 值 |
| --- | --- |
| 封存 | `BLOCKED_GOOD` |
| 验收器 | **未改** |
| 技能层 | **未改** |
| 新增机器人运行 | **无**（复用归档） |

## 不宣称

- 不宣称 25% 是精确值（32 个实例 × 2 次，区间宽）；
- 不宣称「没有稳定失败的实例」可外推到更多重复（2 次重复不足以发现低频稳定失败）；
- 不宣称翻转的原因已查明（很可能与释放 stall 的随机性同源，**未证**）；
- **未上真机，M0**。

## 下一步该怎么做（诚实地说）

任何关于**比率**的结论都需要**每实例多次重复**。
在那之前，能可靠报告的是**机制性证据**（某步骤是否运行、某决策是否被记录），
而不是通过率的小幅变化。
