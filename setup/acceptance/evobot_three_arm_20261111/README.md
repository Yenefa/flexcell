# 三臂对比补齐：A′ 0/16、B 16/16、C 16/16

## 此前缺失什么

使命要求维持**三臂基线**（FSM / Runtime Agent / Self-Evolving）。
但 A′ 此前**只测过** T01/T02/T04/T05，
**从未在 B 和 C 被测量的那 16 个未见实例上跑过**。
所以「三臂对比」一直是不完整的。

## 这轮补齐

A′ 是纯规则、无 LLM、无需 Gazebo，所以对比**便宜且精确**：
三臂收到**完全相同的 observation 对象**。

## 规划层结果（对照封存答案）

| 臂 | 计划正确 | 说明 |
| --- | --- | --- |
| **A′**（FSM 规则） | **0/16** | **16/16 全部拒绝**「no rule matches this instruction」 |
| **B**（Runtime Agent） | **16/16** | 全部正确 |
| **C**（Self-Evolving） | **16/16** | **与 B 完全相同** |

## 这三个数字各自说明什么

### A′ = 0/16 是**正确的 FSM 基线行为**

规则引擎对未见指令**诚实地拒绝**，而不是瞎猜。
前几轮 A′ 能解 T01/T02/T04（所以那些模板没有区分力），
但那只是模板覆盖，不是泛化。

**在真正未见的任务上，规则基线 = 0。** 这正是 Agent 存在的理由。

### B = 16/16 说明瓶颈不在规划

与此前 `evobot_unseen_n6` 的结论一致：agent 规划 6/6 正确。
现在扩到 16/16。**执行层的失败不能归因于规划。**

### C = 16/16 与 B 完全相同，是**更强的负面结论**

结合上轮的机制发现：
- C 确实收到了教训（16/16 都检索到 1 条）；
- 计划仍字节相同；
- 因为剩余失败是**执行层**，而执行知识已在代码里。
