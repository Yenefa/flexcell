# P2 第 ② 项 — agent 自主归纳经验：**三次尝试全部未达成**

## 目标要求
24H 目标 §4 要求区分三件事，其中第 ② 项是"**Agent 从执行反馈中自主归纳的经验**"。
此前所有经验记录都是**我（工程师）**写的；本实验让 agent 自己写。

## 设计
修复成功后，追加一个 **write-up 阶段**，要求 agent 调用 `record_experience`，
字段为 `defect_class` / `symptom` / `lesson` / `evidence_path`。

**机械校验拒绝编造**（写在代码里，不是提示词）：
- `evidence_path` 必须**真实存在**于工作区，否则拒绝；
- `lesson` 少于 20 字符拒绝；
- `defect_class` 为空拒绝。

## 三次尝试

| # | 迭代 | Token | 修复 | 是否给了 write-up 轮 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 1 | 3 | 14,918 | **PASS** | **否**（harness 缺陷） | 0 次记录 |
| 2 | 4 | 20,873 | **PASS** | 是 | agent **又跑了一遍场景**，未记录 |
| 3 | 3 | 23,958 | **PASS** | 是，且工具箱收窄到 `record_experience`+`read_file` | agent 尝试 `read_telemetry`（被拒），仍未记录 |

### 第 1 次是 harness 缺陷
`runner.py` 在判定 PASS 时**立即 break**，agent 根本没拿到 write-up 那一轮。
因此本次**不能**算作"agent 不写"的证据。已加可选的 `post_pass` 钩子（默认关闭，不影响历史结果）。

### 第 2、3 次是真实行为
- 第 2 次：明确要求"不要再跑场景，写下来"，agent **仍然又运行了场景**；
- 第 3 次：把工具箱收窄到只剩记录与读取，agent **仍在试图获取更多证据**（`read_telemetry` 被拒），
  始终没有调用记录工具。

## 判读

**第 ② 项未达成。** 失败机制不是"不会写"，而是**在任务完成后仍持续倾向于继续获取证据，
而不是沉淀结论**。三次尝试、三种不同的推动方式（提示、强制轮次、收窄工具），均未改变该倾向。

## 边界
- n=1 / 配置，三次属于**同一配置的不同推动手段**，不是独立重复；
- 修复本身每次都成功（三门 PASS），所以这**不是能力问题**，是行为偏好问题；
- **不影响第 ③ 项**：`p2_reuse_budget_20261110` 已证明 agent 会**读取并使用**他人写的经验。
