## 这证明了什么，没证明什么

| 证明了 | 没证明 |
| --- | --- |
| T01–T06 的**规划层**已被确定性正则完全覆盖 | 机器人**执行**会成功——计划不是执行 |
| 在这些模板上，LLM 的**可测量规划价值为零** | 规则能泛化到没见过的任务类型（它不能） |

**等级：plan-layer only。这不是成功率，不能当成功率引用。**

## 为什么这个测量是诚实的，尽管规则是看完模板才写的

看完六条指令再写规则，覆盖率必然高，**所以这个分数不证明泛化**。
它证明的是另一件事，也正是 mission 要求的：**简单规则能否达到同等表现**。

答案：能，在这六个模板上完全能。

对照项目自己的更早记录：

| 版本 | 何时写的规则 | 结果 |
| --- | --- | --- |
| A′（旧） | **看模板之前** | 0/16，诚实拒绝 |
| A′-new | **看模板之后** | 64/64（T12–T14 族） |
| 本卡 | **看模板之后** | **72/72（T01–T06 族）** |

旧 A′ 说明「规则不能泛化到没见过的新任务类型」。
新 A′ 说明「一旦知道类型，正则就够」。
**两条合起来推出：T01–T06 不能用来证明 agent 优势。**

## 对项目叙事的硬约束

- **禁止**用 T01–T06 上的 agent 成绩宣称「智能优势」——同样的成绩一个正则就能拿到
- agent 的增量价值必须展示在**规则失败**的任务上
- 这正是 P2（T08 推动）存在的理由：现有技能 + 规则**都做不到**，才值得做

## 一个被测量抓到的自身缺陷

第一版规则对 T05/T06 返回 `unmoved=[]`，而 spec 期望未移动的另一只方块。
结果 placement 和 visit 全对、只有 `unmoved_ok` 失败 → **12/12 变成 0/12**。
修的是规则（把未移动物体填回去），不是评分标准。
