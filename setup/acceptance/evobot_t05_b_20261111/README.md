# T05 中转任务 — 第一个真正区分两臂的结果

**指令：** "Move the blue block to the left bin, passing through the right bin first."

## 结果对比

| | A′ 确定性规则（无 LLM） | **B Agent** |
| --- | --- | --- |
| 能否规划 | **不能** | **能** |
| 拒绝理由 | `no rule matches this instruction` | — |
| 计划 | — | `box_b→zone_1`，`box_b→zone_2` |
| 执行 | — | 两个阶段均完成 |
| 独立验收 | — | **PASS** |

## 关键：路线真的被判分了，不是只看终点
```json
"visit:target_box_b": {
  "required": ["zone_1"],
  "observed": ["zone_1", "zone_2"],
  "ok": true
}
```

如果中转路线不判分，**直接搬运也会通过**，那 T05 就不是中转任务。
为此给验收器加了 `visit` 子句，从 `place.jsonl` 的历史落点推导实际经过的箱子。

新增测试断言：**直接搬运必须判 FAIL**（`test_t05_direct_move_fails_even_with_the_right_destination`）。

## 途中发现并修掉的三个真实缺陷

### 1. clearance 常量从未与场景几何核对
`clearance_m = 0.060` 是从服务端配置默认值抄来的。实测：
`box_a` 初始位置到 `zone_2` 中心只有 **58.3 mm**，而 clearance 是 **60 mm**。

结果：任何"把物体放进 zone_2 且 box_a 不动"的任务都被判为**不可行**，
包括 T05。差 **1.7 mm**。

修正：clearance 由物体尺寸推导并夹到契约区间 `[0.05, 0.25]`（Action 契约规定）。
**验收半径 0.06 m 未改动**——改的是规划器的占用声明，不是验收标准。

### 2. 我的校验器禁止正确的中转计划
`validate_plan` 有一条"同一物体不能出现两次"，但 `RunComposite` 契约**明确允许重复物体名**，
而中转任务**恰恰需要**同一物体移动两次。我的守卫会把正确计划判成非法。
已改为允许重复。

### 3. `$NAMES2` 未定义
重排脚本步骤时把赋值和引用改名不同步，导致观测里物体列表为空（`0/0`）。
**这是脚本 bug，不是机器人问题**——但它会让"没观测到"伪装成"任务失败"。

## 没有证明什么

- **n=1 实例**。
- 只证明 B 能规划中转，**没有**证明 B 在更复杂任务上仍优于规则。
- 未跑 held-out。
- 仍是 Level 2（Compose）的**候选**，需要多实例 + 回归才敢宣称。
