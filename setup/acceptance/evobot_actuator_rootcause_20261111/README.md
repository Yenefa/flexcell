# 找到剩余失败的唯一根因：夹爪释放时卡死

## 23 轮以来我一直在错误的层面上归因

剩余失败被反复描述为：
- `err 62 native terminal/verification unconfirmed`（策略层包装）
- `PLACE_A:FAIL`（还是包装）
- 「抓放失败」（我的猜测）

**这些全都是包装层的话。** 真正的执行器记录在 `episode` 文件里，
而 journal 里的 `episode_path` 字段一直在告诉我位置——**我此前从没打开过它**。

## 真实原因（4 例完全相同）

```
gripper did not open (position=-0.011, requested=0.02, stalled=True)
```

**夹爪想张开（0.02）却卡在 −0.011，`stalled=True`。**
箱子因此从未释放，阶段无法提交。

`stalled` 的语义是「钳口停在障碍物上，未到达请求开度」。
**这是执行器事件，不是规划错误，也不是经验问题。**

## 关键证据：同一个落点，有时成功有时卡死

| 落点 | 卡死 | 成功 |
| --- | --- | --- |
| (0.205, 0.050) | 2 | 4 |
| (0.120, −0.195) | 2 | 4 |

**同一坐标既成功又卡死 → 不是几何、不是规划、不是可达性。**
若是几何问题，同一落点不可能出现两种结果。

## 16 例的完整画像

| 根因 | 数量 | B 首试 | R 最终 |
| --- | --- | --- | --- |
| `ACTUATOR_STALL_ON_RELEASE` | **4** | 0/4 | **3/4** |
| 无执行器故障 | 12 | 12/12 | 12/12 |
| **合计** | 16 | 12/16 | **15/16** |

**剩余 1 例失败 = 同一个 stall 在两次尝试中都发生。**

## 这意味着什么

1. **恢复机制对这唯一剩余失败源有效 3/4** —— 重试确实能躲过瞬时卡死；
2. **剩下那 1 例不是能力问题**：同一动作重复两次都被卡住，
   属于执行器/物理层面的间歇故障；
3. **继续改规划、改恢复、加经验都不会有帮助** —— 它们都不是瓶颈。
