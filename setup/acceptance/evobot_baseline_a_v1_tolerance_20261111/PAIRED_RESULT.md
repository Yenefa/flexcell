# A-v1 容差对照：结果（2026-11-11 19:30）

## 结论：容差不是变量，位置/负载才是

| 实例               | A-v0 批次（末尾执行）           | 冷机器 tol=0.02                      | 冷机器 tol=0.06        |
| ------------------ | ------------------------------- | ------------------------------------ | ---------------------- |
| T05-train-seed1000 | **FAIL**，`set_pose rejected=6` | **PASS**，`rejected=0`，两阶段全提交 | **PASS**，`rejected=0` |
| T05-train-seed1001 | **FAIL**，`set_pose rejected=6` | **PASS**，`rejected=0`，两阶段全提交 | **PASS**，`rejected=0` |

**tol=0.02 与 tol=0.06 结果完全一致。** 提高容差没有救回任何东西，也没有放行任何假成功。

## 这次实验证伪了什么

| 假设                                               | 状态                       | 证据                                          |
| -------------------------------------------------- | -------------------------- | --------------------------------------------- |
| 「T05/T06 模板本身跑不通」                         | **证伪**                   | 冷机器上两阶段全部 `COMMITTED`，独立验收 PASS |
| 「`position_tolerance_m=0.02` 太严，是假失败主因」 | **证伪**                   | 0.02 在冷机器上就通过；改 0.06 无任何变化     |
| 「机器状态（负载/位置）是主因」                    | **成立（待位置对照终验）** | 冷跑 `rejected=0` vs 热跑 `rejected=6`        |

## 副作用检查

按用户裁决要求检查了「0.06 是否允许其他物体过大漂移 / 错误完成中转阶段 / 掩盖新的执行异常」：

- 两个臂的 `committed` 阶段数相同（都是 2），独立验收都 PASS，`failed_clauses` 都为空
- **没有观察到 0.06 引入假成功**，但样本只有 2 个实例，不足以声称「0.06 是安全的」
- 因此 **A-v1 不采用**。理由不是它有害，而是它**没有证明有用**：真正的变量是机器状态，
  改容差既不解决问题，也不带来风险，纯属无效操作

## 对 A-v0 基线的影响

**A-v0 的 61.1% 是机器状态的函数，不是机器人能力的函数。**

批次按 T01→T06 顺序跑，负载累积，末尾的模板被系统性压低。这意味着：

- 44/72 这个数字**不能**作为「Baseline A 能力」引用
- 任何把 agent 结果与这个 61.1% 对比的做法都是无效的——除非 agent 也在同样负载下跑
- 正确的基线测法：**每个实例独立冷启动**，或**随机化执行顺序**，让位置效应均摊
