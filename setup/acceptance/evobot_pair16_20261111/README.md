# n=16 配对：B（无恢复）vs R（有恢复）+ 避障修复

## 为什么做

之前所有「恢复率」的分母都太小（1/2、0/2、1/4）。同时 v0.2 未见任务只有 6 个实例。
本轮把 n 扩到 **16**，并用**同一次运行**同时测出两臂：

- **B（无恢复）** = 第一次尝试的结果；
- **R（有恢复）** = 有界重试后的最终结果。

同一计划、同一世界、同一验收器、同一封存答案——**配对是精确的**，
批次间方差无法解释任何差异。

## 第一次跑（修复前）：暴露 6 例同源失败

| 指标 | 值 |
| --- | --- |
| B 首试通过 | **9/16** |
| R 最终通过 | 10/16 |
| 配对转移 | both=9, gained=1, lost=0, neither=6 |
| Harness 失败 | **0** |

6 例 `err 60 declared destination occupied at target_box_a-2`，
**respread 之后完全一样**。

### 归因（6 例完全相同）
```
T12 三次访问 zone_1：落点 0.075 和 0.165（沿 x 偏移）
box_b 起始 (0.20, -0.18)
distance((0.165,-0.15), (0.20,-0.18)) = 0.046 m  <  clearance 0.050 m
```
**偏移方向撞上了另一个物体。** 沿单一固定轴扩散不够——
间距够了，但方向错了。

## 修复：偏移轴必须避开其他物体

`spread(stages, avoid=[...])` 现在会比较 x 轴与 y 轴两种扩散方案，
选**留出更大安全距离**的那个；若两个方向都无法满足 clearance，则**明确拒绝**。

实测：y 轴方案下最近距离 0.081 m > clearance 0.050 m ✓

### 这是**加大安全距离**，不是放宽阈值
| 参数 | 改动 |
| --- | --- |
| clearance 契约 | **未动**（0.050） |
| 箱半径 | **未动**（0.060） |
| 落点间距 | **未动**（0.090） |
| 偏移轴选择 | **新增**（原来总是 x） |

## 两个数字要分开读

1. **9/16 → 13/16 是避障修复带来的，不是恢复**。
   修复后 4 个任务首试就过，不再需要恢复。
2. **恢复额外贡献 +1**：`HO-4c174b133d05` 与 `HO-b3bcb892cef6` 首试 `err 62`，
   resume 后 `err 0` 并通过独立验收。`gained=1, lost=0` 意味着**恢复没有让任何任务变差**。

样本外推要谨慎：恢复只在 **2** 个案例上被触发，1/2 = 50% 的置信区间极宽。

## 剩余 2 例失败：协议正确拒绝猜

`HO-4911cf199a42`、`HO-bc8270332865`：`err 62` 在**第一阶段**就失败，
`completed_stage_ids` 为空，detail 里没有判别信息。

分类器返回：
```json
{"action": "no_recovery", "failure_class": "UNKNOWN",
 "measured_reason": "component failed (code 62); no discriminator"}
```

**这是协议在工作，不是缺陷。** 没有证据就不猜——
硬编一个映射只为了触发恢复，正是「伪造修复」的开始。
要减少这类失败，需要**更多判别信息**（例如从 composite journal 取 native 子结果），
而不是放宽分类器。
