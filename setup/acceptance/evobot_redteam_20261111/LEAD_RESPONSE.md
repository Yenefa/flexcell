# 对 red-team 审计的逐条对账（Lead 自己做的更正）

审计对象是我自己最近八轮的工作。结论：**2 个 blocker 成立，核心叙事有实质错误。**
这份文件只做一件事——把每一条判定为**成立 / 部分成立 / 不成立**，并给出证据。

## Blocker

### B1 成立：`GRASP_FRAC` 从未真正生效，「高度不是杠杆」这个否证不存在

`geom_runner.py` 里 `grasp_z(0.5)` / `grasp_z(0.75)` 是**硬编码**，`GRASP_FRAC` 只进了日志字符串和 JSON 字段。

我验证：`mid_*.json` 的日志写 `(midpoint)`，而落盘脚本输出的是 `(frac %.2f of the measured extent)`，
**两者不可能同源**。所以「0.5 / 0.70 / 0.85 三个比例都是 2/5，因此高度不是杠杆」这句话，
**背后没有做过这个实验**。

严重性：**高**。我用一个不存在的否证去排除了一个真实假设。

### B2 部分成立：`geom_rbound` 确实是包围球半径，但 2.7× 的倍率不成立

我实测（`evobot_rbound_check.py` / `evobot_extent_compare.py`，结算后按真实网格顶点算）：

| 物体 | 旧公式（rbound） | **真实顶点范围** | 倍率 |
| --- | --- | --- | --- |
| salad_dressing | 0.1867 | **0.1605** | 1.16× |
| ketchup | 0.1871 | **0.1486** | 1.26× |
| alphabet_soup | 0.1311 | **0.0836** | 1.57× |

**成立的部分**：`geom_rbound` 是包围球半径，用它当半高在概念上就是错的；
四个 runner 共用同一段代码；旧公式还把 `z_lo` 压到桌面以下（-0.027 ~ -0.032），中点因此偏低。

**不成立的部分**：真实倍率是 **1.16–1.57×**，不是 2.70–2.84×。
red-team 引用的「上游资产 XML 真实高度 0.0658 m」与 MuJoCo 里实际加载的网格不符，
可能它量的是另一个轴或另一份资产。**这个数字我不采用。**

**中点误差实测**：salad -4.6mm、ketchup -10.8mm、alphabet_soup 0.0mm。
所以「抓取目标落在碗顶面上方 4.8–13.9cm」这个量级描述，我这边测不出支撑。

### B2 的正确结论

公式确实错，**但它是否是 0/10 的唯一机制，尚未被证明**。
我原本准备把「碗抓不住」归因到它——**现在不能这么做**，因为中点误差只有毫米量级，
而队友测到的碗失败是「夹爪在碗顶上方 4.8cm 合拢」。两者差两个数量级，**不是同一个原因**。
