# 能力阶梯改为**真正派生**：文档不再能漂移

## 原文档的两个问题

1. **自称不是手写状态表**：「每一行的依据都能用一条命令重跑」——
   **但它确实是手写的**，于是漂移了：

| 文档声称 | 仓库实际 |
| --- | --- |
| 17 个批次 | **32** |
| 116 个测试 | **229** |

2. **在被撤回的零下面继续断言那个零**：
   文档顶部的横幅说「0/32 是空的，已撤回」，
   但下面的「关键数字」表仍写着 `False Success Rate 0.0%`。

**一份会漂移的状态文档比没有更糟，因为它会被相信。**

## 现在由脚本生成

```bash
python3 experiments/baselines/capability_ladder.py
```

每个数字都从归档证据读取或当场重算：

| 数字 | 来源 |
| --- | --- |
| 批次 / 验证器失败 | `evobot_evidence_index.json` |
| 离线测试数 | 当场 `pytest --collect-only` |
| B / R 通过率 | 重算三个批次目录 + Wilson 区间 |
| False Success | 重算，仅统计 `claim_source=measured` |
| False Failure | 重算，比对 `task.out` 与验收器 |
| 提案状态 | 读 `evolution/proposals/*.json` 的 `approved` |

**级别状态仍是判断**，但判断写在它所依据的测量旁边，
所以读者可以不同意阈值，而不必先相信标签。

## 加测试防止再次漂移

| 测试 | 内容 |
| --- | --- |
| 声明自己由脚本生成 | 文档必须写明生成器与「请勿手工编辑」 |
| 批次数与索引一致 | 三处计数逐字比对 |
| 测试数与实际收集数一致 | 当场跑 `pytest --collect-only` 比对 |
| **两个方向都必须报** | 只有 false success 就算失败 |
| 零必须带限定 | 出现零时必须同时出现「不可测量」或「区间上界不为 0」 |
| 待批提案必须标未批准 | 读 JSON 的 `approved` |

## 我又修掉一个自己造的脆弱点

最初的测试**依赖执行顺序**：靠前一个测试顺带重新生成文档，
后一个测试才拿到新数字。

**换个顺序就会失败。** 这正是「隐藏耦合」——和之前运行器里 cwd 残留同一类问题。
已改为每个相关测试自行重新生成。
