# 修好了两个盲点中的一个，仍然不采纳

## 上轮的遗留问题

确定性检查的容差（20mm）大于计划目标到区边的余量（15mm），
所以它可能把**区外**的放置判为「已达成」→ false success。

## 这轮的修法：两个条件而不是一个

```
1. 物体在计划的容差内            （执行正确）
2. 物体在该计划阶段所指的区半径内 （被接受）
```

两个条件都只用 agent 能看到的东西：自己的计划、自己的测量、观测里的区半径。
**不读封存答案。**

## 结果（64 次运行）

| 方法 | 覆盖 | 正确 | 错误 | false success | false failure |
| --- | --- | --- | --- | --- | --- |
| 两条件检查 | 40/64 | **40** | 0 | 0 | 0 |
| LLM 自评 | 64/64 | 45 | 19 | 0 | 19 |
| **混合**（能判定时用前者） | **64/64** | **64** | **0** | **0** | **0** |

两条件检查在 24 例上**拒绝判定**，原因全部相同：
「同一物体出现在多个阶段，目标包含位置无法证明的顺序」。
**拒绝不等于失败，它意味着「去问别的机制」。**

## 为什么混合规则不是过拟合

分工是按**能力**分的，不是按数据挑的：

| 组件 | 回答什么问题 |
| --- | --- |
| 确定性检查 | **我执行了我的计划吗**（直接测量） |
| LLM 自评 | **我的计划符合指令吗**（读指令） |

## 但我仍然不采纳，因为剩下那个盲点没修

两条件修的是**容差**问题。**计划本身错误**的问题没修：

```
计划说放 zone_2，实际答案是 zone_1
→ 物体精确落在 zone_2 的计划目标上、且确实在 zone_2 内
→ 两条件检查全部满足 → 声称成功
→ 验收器判失败 → FALSE SUCCESS
```

**这批数据里 64/64 计划都是对的，所以这个风险一次都没被触发过。**
100% 的准确率恰恰来自「计划全都对」，而不是来自「检查能发现计划错」。

## 采纳它的条件

只有把「计划是否符合指令」也变成可判定的时候，才能用它替代自述。
而那正是 LLM 现在承担的部分——**换掉它就把这一层丢了**。
