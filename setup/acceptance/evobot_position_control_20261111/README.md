→ **位置效应成立**：T06 不是坏模板，它是在批次末尾被系统性压低的。

## 两个必须记录的修正

### 1. 两个「失败」其实是基础设施故障

位置 4 与 6 的 `ground_truth.json`：

    "errors": {"target_box_a": "pose stream is not flowing (gz transport may be wedged)", ...}

观测桥拿不到真值 → 验收器看到 `object missing` → 判失败。**机器人可能做对了，也可能做错了，无从知道。**

本脚本第一版**没有带分类器**（A-v0 批次脚本有），因此把基础设施故障记成了任务失败。
已修：现在会检查 `pose stream is not flowing` / `failed to create domain` / `ground_truth` 里的 `errors` 字段。

### 2. T02 的反向对照没有完成

原设计要把一个 T02 实例放到最后，验证「原来通过的模板排到末尾也会失败」。
但那一跑撞上真值流断裂，**证据无效**。所以「位置效应」目前**只有单向证据**：
T06 靠前通过（3/3），没有 T02 靠后失败的配对确认。

## 还不能声称什么

- 不能声称「T02 排到末尾也会失败」——那两次运行无效
- 不能声称位置效应的确切机制（负载？散热？gz 累积状态？）
- 不能声称 A-v0 的 61.1% 是纯位置效应——它同时混有真失败（T04 那 3 个 `rejected>0` 的）
