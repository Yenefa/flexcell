# LIBERO 迁移测试：结构迁移成功，**抓取参数不迁移**（1/3）

## 为什么要做

上轮完成的任务里，物体与篮子是**写死的**。写死的脚本通过一个任务，说明不了任何迁移能力。
所以这轮把控制器改成**从官方 BDDL 的 goal 子句里解析**「物体 + 目标区域」，
策略阶段完全不变，然后跑 3 个官方任务。

## 结果

| index | 任务 | 解析出的目标 | 官方成功 |
| --- | --- | --- | --- |
| 0 | pick_up_the_alphabet_soup... | alphabet_soup_1 → basket_1_contain_region | **True** |
| 1 | pick_up_the_cream_cheese... | cream_cheese_1 → basket_1_contain_region | False |
| 2 | pick_up_the_salad_dressing... | salad_dressing_1 → basket_1_contain_region | False |

**迁移率 1/3。这是一个负面结果，不是一个部分成功。**

## 失败在哪里（逐条看日志）

| 任务 | 现象 |
| --- | --- |
| 1 cream_cheese | 物体几乎没动（z 0.000 → 0.009）→ **根本没抓住** |
| 2 salad_dressing | 只移动 4cm 就停（z 0.035 → 0.073）→ **抓住后滑脱** |

两者都**不是**规划问题、也不是目标解析问题（解析全部正确），
而是**抓取高度是按物体调的**：`o.z + 0.02` 对罐头合适，对扁平盒子和细瓶子不合适。

## 这条结论的价值

它划清了「适配层的结构」与「策略的参数」：

| 层 | 是否迁移 |
| --- | --- |
| 目标解析（BDDL → 物体/区域） | **迁移成功**（3/3 解析正确） |
| 位姿 → delta 闭环 | **迁移成功**（三个任务臂都动起来了） |
| 抓取高度偏移 | **不迁移**（1/3） |

**这就是「真实任务决定下一步要学什么」的具体内容**：下一项能力不是更多任务，
而是**从物体几何自动推导抓取位姿**，而不是手工调一个偏移量。
