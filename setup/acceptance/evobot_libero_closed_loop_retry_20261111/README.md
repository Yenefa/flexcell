# 用测量反馈代替拟合阈值：样本内同样 3/5，留出仍 0/10——但诊断变清楚了

## 上轮的教训直接决定了这轮做什么

上轮按高度阈值选接近方式，样本内 3/5，留出 0/10。
**阈值是在 5 个样本上选的，属于拟合**。再拟合一个常数只会重复同样的错误。

而失败信号**本来就在被测量**：抓成功了物体就抬起来，没抓起来物体不动。
所以这轮不再预测该用哪种方式，而是：**试一次 → 测量是否真的抬起 → 失败就重置、换方式再来**。

判据用物理量：抬升 > 3 cm 才算抓住（`LIFT_PROOF_M`）。

## 结果

### libero_object（上轮阈值就是在这 5 个任务上选的）

| 任务 | 尝试序列（方式, 是否抬起, 是否成功） | 结果 |
| --- | --- | --- |
| 0 | top / 抬起 / 成功 | **True** |
| 1 | top / 抬起 / 成功 | **True** |
| 2 | top 未抬起 → side_x 未抬起 | False |
| 3 | top 未抬起 → side_x 抬起 / 成功 | **True** |
| 4 | top 抬起但释放失败 → side_x 未抬起 | False |

**3/5，与上轮拟合阈值得到的数字相同——但这轮没有任何拟合常数。**
第 3 个任务清楚地展示了闭环在起作用：top 抓不起来，测出来，换 side_x 成功。

### libero_spatial（上轮的留出套件）

10 个任务全部失败，且**两种方式都报 `carried=False`**——

**物体从来没有被抬起来过。**

## 这条诊断比数字更重要

上轮留出 0/10 时我以为是「策略选错了」。
这轮的尝试序列证明：**不是选错，是两种方式都抓不住碗**。

所以重试这个能力**在留出套件上无效，因为失败发生在更上游**。

| 失败层级 | 样本内 | 留出 |
| --- | --- | --- |
| 选错接近方式 | 1 例（任务 3，重试修复） | 0 例 |
| **根本抓不住** | 1 例（任务 2） | **10 例** |

## 不宣称

- 不宣称 3/5 是泛化成绩（它只在这 5 个任务上）；
- 不宣称留出 0/10 是硬件极限（**只是这两种方式抓不住碗**）；
- 不宣称重试无价值（它确实修复了一个选错方式的案例，且**去掉了拟合常数**）；
- 不宣称这是 LLM 规划的成果（全程确定性控制，无 LLM）。

## 这轮真正得到的东西

把「一个拟合出来的选择规则」换成了「一个基于测量的重试循环」，
并且**用留出套件确认了失败发生在哪一层**——这在上一轮是看不出来的。
