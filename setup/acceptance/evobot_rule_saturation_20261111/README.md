# 基准在规划层被**规则解析器打满**：LLM 的可测贡献为零

## 为什么要做这件事

B（LLM 规划器）得分不错，但「不错」只有在**非学习基线不能同样得分**时才有意义。

原始 Baseline A **直接读 `expected_goal`**，是开卷预言机，不是基线。
所以我写了一个**确定性规则解析器**，它只读 B 读的东西：指令、可见物体、可见箱子。

## 结果（同一批 64 个观测）

| 指标 | 值 |
| --- | --- |
| **规则规划器正确** | **64/64** |
| **LLM 规划器正确** | **64/64** |
| 两者计划一致 | **63/64 = 98.4%** |
| 规则器拒绝 | 0 |

**在这三个模板上，规则解析器与 LLM 打平。**

## 我必须先说清一件不光彩的事

这个规则器是**我看了模板之后写的**。
正因如此它**不是泛化基线**——它不能证明「规则也能解没见过的任务」。

它能证明的是另一件、更让基准难堪的事：

> **这三个模板的规划层，可以被针对模板族写的正则完全解决。**

也就是说：**在这个基准上无法展示 LLM 是必要的。**
如果我说「agent 在理解任务」，那是把正则的功劳记在 agent 头上。

## 一个我先搞错、后修正的数据

第一版规则器只拿到 **40/64**，我差点据此说「LLM 带来 +24 例增量」。

查下去是我的解析器**写弱了**：T12 的指令会提到 4 次箱位
（含结尾的 `it must actually visit the <bin>` 一句），我抽成了 **4 步**，正确是 **3 步**。

改成按句子结构解析后，**40/64 → 64/64**。

**「LLM 有增量」这个结论完全来自我自己的 bug。**
若我当时就报出去，会是在用一个解析器缺陷去论证 agent 的价值。

## 与早先 A′ 结果的关系（不矛盾）

| 基线 | 时机 | 结果 | 含义 |
| --- | --- | --- | --- |
| A′（旧） | **看模板之前**写的规则 | 0/16 | 诚实拒绝，不认识新模板 |
| A′-new（本轮） | **看模板之后**写的规则 | 64/64 | 模板族可被正则覆盖 |

两者都对，回答的是不同问题：
- 旧 A′ 说明「规则不能泛化到没见过的新任务类型」；
- 新 A′ 说明「一旦知道类型，正则就够」。

## 对梯子的影响

| 级别 | 之前 | 现在 |
| --- | --- | --- |
| Level 8 Generalize | 已验证（有限） | **需降级**：规划层已饱和，泛化成绩不能证明推理 |

类似 with 之前的教训：**一个能被打满的基准不能证明能力**。

## 不宣称

- 不宣称「LLM 无用」——只宣称**这个基准测不出它的用处**；
- 不宣称规则器能泛化（它是我看模板后写的）；
- 不宣称执行层同理（执行层是真实机器人动作，正则不适用）；
- 不宣称 1 例不一致的原因已查明；
- **未上真机，M0**。

## 下一步该做什么（诚实地说）

要证明 agent 有推理能力，需要**规则器写不出来的任务**：
比如需要多步重新观测、或指令里有只有通过测量才能消除的歧义。
现有的 T12/T13/T14 都做不到这一点。
