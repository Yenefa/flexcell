# 效果验证：命令跑了 ≠ 命令生效

**状态：`PROPOSED`**（测试通过 ≠ 有价值；尚未有回访数据）

---

## 什么时候触发

- 用脚本改文件（`sed -i`、重定向、`python -c` 写文件）之后
- 跑测试/检查命令之后，准备根据输出下结论
- 任何「我做了 X，所以现在 Y」的推理

## 什么时候**不能**用

- 命令本身有可靠的机器可读产物（例如 JSON 输出）→ 直接读产物即可

**本 Skill 只补一件事：给「生效」找正向证据。**

---

## 为什么需要它

本会话三次，全部是同一模式：

### 事件 A —— WSL git 报错，空输出被读成「diff 0 行」

```
git diff --numstat   ->  fatal: not a git repository
输出看起来是空 -> 被判读成「没有差异」
```

**空输出既可能是「没有差异」，也可能是「命令失败」。没看退出码就无法区分。**

### 事件 B —— `sed -i` 权限失败，变异没做成

```
sed: couldn't open temporary file benchmark/evaluators/sedBN4Nbh: Permission denied
-> 退出码非 0，但我没检查
-> 以为变异做了，测试「仍然全绿」，差点得出「测试不会失败」的错误结论
```

**如果不检查退出码，这件事会被记成「测试无效」，而事实是「变异无效」。**

### 事件 C —— `cd $W` 变量未赋值

```bash
cd $W          # W 未赋值为空 -> cd 回家目录
pytest ...     -> "no tests ran"
```

**「no tests ran」被我读成「测试通过」。** 实际是根本没跑到测试。

---

## 必做步骤

```bash
# 改文件后：确认内容真的变了
python3 scripts/effect_check.py changed <file> --against <backup>

# 跑命令后：确认输出里有成功标志
python3 scripts/effect_check.py contains "<output>" PASSED
```

## 核心规则

| 情形           | 不是成功       | 是成功                     |
| -------------- | -------------- | -------------------------- |
| 命令退出码     | 只看这个       | 退出码 **且** 产物符合预期 |
| 输出为空       | 可能是失败     | 必须证明「空是预期」       |
| `no tests ran` | **绝不是通过** | 必须有 `N passed`          |
| 文件已改       | 不算           | 内容哈希变了才算           |

## 验证方法

```bash
python3 -m pytest tests/ -q
```

## 失败时如何安全退出

```
没有正向证据 -> 报告 UNKNOWN，不要报告成功
```

## 适用范围

| 覆盖                    | 不覆盖             |
| ----------------------- | ------------------ |
| 文件改动是否发生        | 改动是否正确       |
| 命令输出是否含成功标志  | 标志是否被正确实现 |
| 空输出/空结果的显式处理 | 业务逻辑正确性     |
