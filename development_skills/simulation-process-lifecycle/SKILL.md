# 仿真进程生命周期安全

**状态：`PROPOSED`**（测试通过 ≠ 有价值；尚未有回访数据）

---

## 什么时候触发

- 要写/改一个清理仿真进程的脚本
- 批处理跑完后要确认没有残留
- 一次运行的结果与上一次差异很大，怀疑机器上有残留进程
- 用了 `pkill` / `killall` / `kill` 中的任何一个

## 什么时候**不能**用

- 杀的是本进程自己的子进程 → 用 PID / PGID，不要用模式匹配
- 需要跨机器清理 → 这是另一个问题

**能用 PID 就不要用模式匹配。模式匹配是最后的退路。**

---

## 为什么需要它

本会话两次，都由「清理脚本本身」造成：

### 事件 A —— `pkill -f "[$n]"` 是字符类，不是转义

```bash
n=carry_server
pkill -9 -f "[$n]"        # 展开成 [carry_server]
```

`[carry_server]` 在正则里是**字符集**，匹配「任意一个出现在 c,a,r,y,_,s,e,v 里的单字符」。
实测它匹配了 **4/4** 条无关命令行；正确的 `[c]arry_server` 匹配 **0/4**。

**整个执行链在真正开始前就被杀掉了。**

### 事件 B —— 136 个孤儿进程让一整批测量失效

```
68 × parameter_bridge
68 × robot_state_publisher
ppid 551957（父进程早已退出）
load_after 从 2.48 爬到 19.89
```

后果：

```
A-v0 原始测量: 44/72
清理后重测:    71/72
T06:           0/12  ->  12/12
```

**模板没变、机器人没变、判据没变。变的只是机器上有没有残留进程。**

而当时的孤儿检查只匹配 `'flexcell_skills/'` 一个类，**结构上不可能看见它们**。

## 验证方法

```bash
python3 -m pytest tests/ -q
```

## 失败时如何安全退出

```
匹配数 == 0  -> 什么都没匹配到，不要报「已清理」
匹配数 >= 40 -> 拒绝执行，这几乎肯定误配
```

**「清理成功」必须有匹配数作证，不能只看命令退出码。**
