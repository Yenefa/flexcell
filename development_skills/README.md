# EvoBot 开发能力库（Development Skills）

**这个目录与机器人能力无关。** 它固化的是「怎样可靠地开发、诊断、验收机器人技能」，
不是「机器人怎样推方块」。

| 目录                                    | 内容                   | 属于                  |
| --------------------------------------- | ---------------------- | --------------------- |
| `wt-comp/skills/manipulation/`          | 抓放、推动等机器人技能 | **机器人运行时能力**  |
| `wt-comp/src/flexcell/flexcell_skills/` | 技能服务实现           | **机器人运行时能力**  |
| **`wt-comp/development_skills/`**       | **开发流程经验**       | **开发能力** ← 本目录 |

两者混在一起会让「团队变强」被误读成「机器人变强」。**这是本目录存在的前提。**

---

## Skill Curator —— 固定角色

EvoBot Agent Team 的常驻观察员。**不参与机器人动作规划，不抢 Coding Agent 的活。**

```
OBSERVE → CLASSIFY → CLUSTER → PROPOSE → TEST → REVIEW → PROMOTE → MONITOR
```

### 触发方式：事件驱动，不是每次工具调用

| 触发事件      | 说明            |
| ------------- | --------------- |
| 一次实验失败  | 有新的失败证据  |
| 同类错误复发  | 上次修过又来    |
| PR / 提交完成 | 有可审查的 diff |
| 阶段性验收    | 里程碑后回看    |

**不常驻轮询。** 一个观察员持续烧 Token 会干扰正在跑的仿真，且信息价值低。

### 成功指标不是「造了多少 Skill」

而是：

- 重复错误复发率下降
- 同类任务修复耗时下降
- 无效工具调用减少
- 不引入新失败
- Agent 真的在用它，而不是继续重复探索

## 库结构

```
development_skills/
  README.md                  本文件（契约 + 门槛 + 登记表）
  registry.json              机器可读登记表
  ros2-interface-preflight/  SKILL.md + scripts/ + tests/ + references/
  simulation-process-lifecycle/
  evidence-level-audit/
  effect-verification/
```

每个 Skill 必须有：

- `SKILL.md`：触发条件、**不适用场景**、必做步骤、验证方法、安全退出、证据来源
- `scripts/`：能自动执行的部分写成脚本
- `tests/`：**必须证明能失败**（变异测试）
- `references/`：真实失败案例，可追溯

## 有效性回访（最容易被忽略的一环）

Skill 通过自己的测试，**不等于它有价值**。

每个 Skill 在 `SKILL.md` 里必须写明**回访指标**，并在后续任务中检查：

| 检查项                 | 方法                   |
| ---------------------- | ---------------------- |
| 同类错误是否还发生     | 查新运行的日志/报告    |
| Agent 是否真的调用了它 | 查运行记录里有没有用   |
| 是否引入了新问题       | 对照使用前后的失败类型 |

**没有回访数据的 Skill 状态是 `PROPOSED`，不是 `VERIFIED`。**

---

## 红线

- 不修改独立验收器、冻结基准、成功阈值、历史证据来让 Skill 通过
- 不从未经验证的 Skill 标 `VERIFIED`
- 不把单次成功推广为通用规律
- 不修改活跃运行时环境、实验基线、生产 Skill（需授权，提交审查）
- 不把「写了 Skill 文档」算作开发能力提升
