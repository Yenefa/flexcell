# 失败案例：证据等级混淆（2 次）

## 案例 A —— 65 个测试全绿，生产路径从不调用它

```
verify.py            65 测试全绿（2026-11-12 实测）
evaluate.py v0.4.0   grep 'evidence\|verify_evidence' -> 只有注释，无 import
```

修复（v0.5.0 集成）后立刻暴露第二个错：

```
evaluate.py 调用 verify(bundle, terminal) 但没传 limits
-> 三个限值依赖门 fail closed："no lift limit supplied"
-> 每一次真实推都会被判 NOT_PUSHED
```

**65 个验证器测试 + 8 个集成测试全绿，与「唯一生产路径每次都失败」并存。**

根因：单元测试传了 `fixtures.limits()`，集成测试也是，**而真实调用方没传**。
测试与调用方走的不是同一条路。

## 案例 B —— 报告声称 8/9 门通过，实际 6/9

```
报告原文:  9 门中 8 门通过
修复接线后实测:  9 门中 8 门通过    <- 现在才对
修复前实测:      9 门中 6 门通过    <- 当时是错的
```

**结论对，算术错，而且错的方向是美化工作**（三个失败报成一个）。

## 共同点

| 特征                    | 案例 A   | 案例 B |
| ----------------------- | -------- | ------ |
| 测试/报告看起来支持结论 | ✅       | ✅     |
| 结论与真实不符          | ✅       | ✅     |
| 靠跑真实路径才发现      | ✅       | ✅     |
| 方向                    | 低估失败 | 美化   |

**结论：证据等级必须显式标注，且每个数字都要能复算。**
