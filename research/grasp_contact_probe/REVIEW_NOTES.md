## 2. 评审提出的有效性威胁（已写进 REPORT §6 限制）

1. **"位置伺服压紧 + 摩擦托住" ≠ "力控夹持"**：闭合指令 0.020 m 对 35/50 mm 箱是"压穿"指令，
   伺服被 20 N 上限削顶。要测力控得把 `closed_gap = size − 1 mm`、上限压到 3–5 N，余量只剩 2–3 倍。
2. **统计力有限**：抖动只有 ±1.5 mm / ±2°，5+5 实际是 5 个初始条件 × 2 物体；10/10 只给单侧 95% 下限 ≈ 74%。
3. **缺负控制**：静态全过不能证明摩擦是真的 → 已补 7 个对照（载荷阶梯 0.5/1.0/1.2/1.5 kg、μ=0.2、
   快速抬升、20 mm 箱），并把库仑预测 1.12 kg 写进 `protocol.json:controls` 再跑。
4. **引擎身份不能只信配置字符串** → `run_probe.py` 每 trial 采样 `/proc/<pid>/maps`，
   记录 `libdart.so.6.13.2` / `libgz-physics7-dartsim-plugin.so.7.8.0` 的路径与 sha256。
5. **接触力口径**：`JointForceCmd` 在 PostUpdate 已被清理（恒 0），且接触传感器给的是**单点** wrench 峰值，
   不能当 `μ·N` 里的 `N` → 报告把"指令力 7.50 N"与"实测单点接触力 2.0–2.7 N"分列并注明不可混用。

## 3. 未落地的一条（必须如实记录）

分析员的 `friction_cone_check` 在按"全部 trial"计算观测翻转区间时把不同实验臂混在一起，
于是当轮的 stress 探索报告（`stress-v2`，已被 `stress-v3` 取代）出现"观测翻转区间 1.00–0.03 kg，预测 1.12 kg 不在该区间内"的表述。
正确口径是**按实验臂分组**：

- `load_ladder`（μ=1.0, gap=0.020, lift 0.5 s）：托住 0.50 / 1.00 kg，滑移 1.20 / 1.50 kg
  → bracket **[1.00, 1.20] kg**，预测 1.12 kg ∈ bracket → **一致**；
- `mu_control`（μ=0.20, 0.50 kg）：容量 3.0 N < 载荷 6.7 N → 预测滑移，实测滑移 → 一致；
- `zero_squeeze`（20 mm 箱）：闭合间隙 0.020 = 箱宽 → 指令力 0.03 N、容量 0.06 N → 预测滑移，实测滑移 → 一致（协议边界，非物理失效）。

7/7 一致这个总判定不受影响（它逐 trial 比对，不依赖区间），但上面那句区间表述是错的，以本文件为准。
修复该分组的 commit 未及落地，分析员被中断；原始数据与逐 trial 表未受影响。
